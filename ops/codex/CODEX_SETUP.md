# Codex 开发环境与任务约束

## 开始前

1. 确认当前工作树、分支、提交与 `git status`，保护已有修改。原因：开发目录可以包含用户尚未提交的工作。
2. 根据任务确定允许路径、目标和验收范围。原因：局部清理或修复不应扩大为架构改造。
3. 读取相关代码、配置与现行规范；涉及数据结构再读取对应迁移。原因：实际实现比历史目录示例更能说明影响范围。
4. 确有隔离需要时使用分支或 worktree，记录其路径和基线。原因：隔离并行改动需要可追溯起点，但每个小任务不需要新的工作树。

## 执行与交付

1. 按用户已授权的范围修改和验证，未执行的测试明确列出。原因：没有执行记录就不能声称验证通过。
2. 完成后说明改动、影响、证据、尚未验证项和适用的回退方式。原因：接手者需要判断能否继续发布。
3. 涉及高风险 Agent 任务时遵守现有审核闸门，发布操作按实际部署入口执行。原因：`human_review_gate.py` 和服务器发布脚本各自检查不同条件。
4. 生产任务使用所需的最小权限，日志中不输出凭证。原因：任务授权不等于可以泄露密钥或扩大数据库权限。

# FQP Merge Gate

Use `python3 -I -S -B .vibe/quality_gate.py --repo .` before merge. The isolated interpreter skips environment-injected Python modules and bytecode; the wrapper also verifies it was launched with these flags. Configure the single intended GitHub repository and PR in `.vibe/config.yaml`; command-line overrides are intentionally unavailable. The wrapper requires a clean checkout, confirms that every DAG task and acceptance is complete, reviews and security/migration evidence are explicitly PASS or NOT_APPLICABLE, the selected open PR points at this exact checkout and targets `main`, and every configured GitHub CI job passes on the live PR head. It re-reads the PR after checking CI and requires the same head OID before proceeding, then rechecks the local branch, revision, and cleanliness. It then invokes the shared V4 `gate merge` command with the V4-compatible argument order.

The configured engine path is only a source location. Before execution, the wrapper requires the exact Python file set and SHA-256 values in `.vibe/engine-lock.json`, copies those verified sources to a fresh temporary directory, and executes that copy in isolated mode. The wrapper resolves `gh` once from the local PATH and treats the installed GitHub CLI and local shell environment as trusted prerequisites.

Do not use the shared engine's `gate merge` result by itself for this repository: the shared engine does not reject `PENDING` review fields or query live GitHub checks. The `reviews.status` field remains `BLOCKER` until the V4 migration review and final PR CI have passed, so a direct engine call also stays blocked. The V4 state transition to `READY_TO_MERGE` must follow a successful wrapper run.

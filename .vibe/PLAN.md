# P117 实施计划

## 范围

交付“服务器新版本提示并强制重新登录”。修改限定于服务器发布脚本写入唯一发布标识、Redis 会话版本标记、公开 release endpoint、登录状态初始化和轮询、不可关闭更新提示及中英文文案/样式。

## 实施顺序

1. 服务器部署和回滚时原子写入唯一 release ID；直接启动时以 Git 提交号作为后备。
2. 登录时保存 release ID；所有受保护 API 拒绝旧 release 会话；`/me` 返回明确的部署变更原因，登出清理 cookie。
3. 前端启动时识别旧 session；已登录页轮询 release，并在变化时显示强制更新对话框。确认后清理旧 cookie、刷新页面并进入登录页。
4. 为 Redis 会话版本绑定、旧会话拒绝、部署状态接口、登出清理和前端强制更新弹窗补充本地回归用例；运行隔离认证与前端测试。
5. 检查差异、敏感信息、错误处理、受保护路由范围和变更预算；通过质量门禁后再准备 GitHub 与服务器发布。

## 验收

唯一验收项 A117，见 `ACCEPTANCE.md`。无数据库迁移、无依赖。用户继续指示后授权本地测试和部署；仅运行隔离认证验证，不调用供应商或生产数据库。

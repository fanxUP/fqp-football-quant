# 2026-10-19 数据污染审计误报修复

## 目标与根因

修复 `error_analysis_scope` 把历史错误分析记录与后来生成的预测比较，导致当时有效的旧预测被报成污染。排查到的 7 条记录都是有效预测，且各自是其预测批次的 SPF 最高概率选项；误报源于审计只保留每个选项的全局最新行。

## 计划

1. 保留近期 72 小时审计范围。
2. 用 `match_id + model_version_id + predict_time` 标识预测快照，并在该快照内对有效、独立模型的 SPF 选项排名。
3. 只在错误记录链接的预测 ID 不是其快照第一名时报告范围异常；不改数据库 schema、错误记录或健康指标逻辑。
4. 补充针对预测时间快照的固定回归用例，运行目标测试及本地质量检查。
5. 推送修复分支并等待 GitHub CI；CI 通过后合并到 `main`。
6. 按代码发布流程部署到 100.121.47.26，记录回滚提交和发布前备份证据。
7. 重跑数据污染审计，只刷新审计结果表；核对旧 7 条误报已解除，并确认没有新的真实异常。

本轮用户已明确授权“测试并部署”。禁止修改预测记录、错误分析明细、schema 或迁移；审计刷新仅写审计日志/解析状态。

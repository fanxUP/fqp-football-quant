# P128 — 体彩传统足彩官方期次目录与历史回填

## 目标

让 14 场胜负彩、任选 9 场、6 场半全场、4 场进球共用体彩官方期次/选场目录。先保存官方来源期号、场序、比赛日精度、官方比分及玩法结果码，再以明确的修复清单与有界批次回填五年历史。开球时间、比赛身份和赛季归属没有来源证据时保持未知。

## 本批实施范围

- 追加迁移128的传统玩法来源字段与目录视图输出；不改`official_matches`、`official_results`、既有赔率或模型概率。
- 将实时采集器保存的比赛时间精度区分为日期、分钟、秒和未知；旧期次仍保留，目录按比赛日期筛选。
- 修正现有14场误标为半全场的期次，并提供只读计划、显式应用的类型修正工具。
- 增加有界、可复核、幂等的新增期次/精确补证导入器；存在槽位、玩法、源ID或比分冲突时整期拦截。
- 保持单`main`分支；不增加包，不推断竞彩ID、fixture或season，不训练模型，不创建备份。

## 顺序与验收

1. 本地实现及固定样本/隔离 PostgreSQL/前端回归：已完成，详见`plans/local-football-data-integration-20261029/traditional-catalog-20261101/RESULT.md`。首个精确提交 CI 又暴露两个既有 PostgreSQL 夹具问题：pool 测试夹具未加载迁移128、观测截止时间测试使用已过期的固定开球日；已将这两处修复纳入本批验收范围。
2. 独立代码、迁移和安全只读审查；形成目标提交并让 GitHub `main` 的 `CI` 工作流在该提交上通过。
3. 生成与目标提交绑定的新鲜发布证据，只部署迁移128；不把旧生产快照或演练当作生产执行证明。
4. 迁移后重新只读读取生产期次、成员和引用，重新生成类型修复计划及API完整导入清单。
5. 按计划独立应用类型修复，再分批导入；逐批核对写入回执、成员与来源证据。任何新冲突都停止对应批次。

## 不纳入本批

不自动补造体彩未提供的开球时分，不将传统足彩比赛强行映射到竞彩官方场次/统一fixture/赛季，不重做已结束比赛的赛前预测，也不把历史回填等同于模型效果验证。

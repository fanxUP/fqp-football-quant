# P105-WEATHER — P104 天气观测时效改善

## 目标

在不放宽 P104 气温 6 小时新鲜度、不改变任何模型输入契约的前提下，将天气采集从每天两次改为每 4 小时一次，使可用比赛天气观测更可能覆盖影子消费时点。

## 本批范围

- APScheduler 天气 CronTrigger 显式按 Asia/Shanghai 时区在 00:07、04:07、08:07、12:07、16:07、20:07 执行，不受全局 `FQP_TIMEZONE` 覆盖影响。
- 运维状态页展示相同的执行时刻。
- 同步采集器模块头说明，让排程来源统一指向 scheduler，避免保留旧的每日两次时刻。
- 保持现有每轮最多 50 场、每个 HTTP 请求最多 3 次尝试；单次成功基线约 300 次/日，保守上界约 900 次/日。该估算只计本采集器，其他共用 IP 的调用仍需纳入观察。
- 用固定本地测试锁定四小时周期、分钟和状态页说明。

## 不在本批范围

- 不推断、抓取或回填竞彩足球逐场停售时间；本次生产 payload 检查没有提供该字段。
- 不修改 Open-Meteo 字段、6 小时有效期、天气公式、P105/P121 消费者、数据库、外部 API 或发布行为。
- 不连接生产库、不调用生产数据源、不提交、推送、合并或部署。

## 验收

见 `ACCEPTANCE.md` 的 A105-WEATHER。完整 A105 与真实 P121 影子概率仍须另有合格生产样本及消费回执才能关闭。

## 风险

每 4 小时采集会增加 Open-Meteo 请求量；预计约 300 次/日，按当前最多 3 次请求尝试估算的保守上界约 900 次/日。若实际可用场数、共享 IP 用量或服务条款变化，应先收紧候选集或调整周期，并保持 P104 的 stale/unknown 降级行为。

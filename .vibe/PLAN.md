# P136 计划：比赛实际赛果事实层

## 目标

在共享 fixture 身份之上增加一层不可变的比赛实际赛果观察。它与 体彩期次结算事实分开保存，保留来源、原始记录、实际比赛日期、状态及比分语义，给后续回填和模型消费提供可审计入口。

## 顺序

1. RED：为来源链接/fixture不一致、状态与比分语义、可训练范围、幂等重放、追加修订和运行角色权限建立隔离 PostgreSQL 用例。
2. GREEN：新增 SQL 130 与最小存储模块；数据库端落实来源绑定、摘要、不可变保护和运行角色 ACL。
3. 验证模型准入视图只暴露实际比赛日期已知、明确完赛、场上、常规时间且有全场比分的数据；未知日期/时长、提前结束、取消、延期、判罚和来源冲突不进入该视图。
4. 将迁移 130 纳入数据库初始化、精确 SHA 发布策略及无备份迁移演练校验；更新身份层设计文档。
5. 执行固定样本、隔离 PostgreSQL、发布策略回归、静态检查和 scope/budget；复核后再进入 GitHub CI 与服务器空结构部署。

## 不在本批

本批不把 Titan/其他网站比分写进生产、不修改 `official_results`、彩票池比分/结果码或现有训练输入，不做历史赛果批量导入。数据入库与模型读取分别按后续批次验收。

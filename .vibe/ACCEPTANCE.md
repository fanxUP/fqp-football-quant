# P132 验收：传统足彩比赛身份别名

## 目标
将已由同一体彩 MatchId 证明的传统玩法物理比赛记录，映射到既有官方竞彩比赛身份。保留现有传统期次成员、来源链接和历史修订，不重写或删除旧记录。

## 必须满足
- SQL 129 只追加不可变别名关系；每个别名只指向一个规范比赛，规范比赛直接具备同一 `sporttery/jc.matchId` 来源链接。
- 拒绝自指、链式别名、重复规范目标、非官方 MatchId 和别名侧存在赛季成员/非传统来源链接的行；并发插入也不能绕过链约束。
- 别名建立后，来源链接、期次成员或赛季成员写入不得使别名证据失效；普通非身份字段更新仍可按原业务路径运行。
- `football_pool_fixture_catalog` 的字段顺序、字段名、字段类型和行数保持不变；有别名时投影规范 fixture 与 official match ID，无别名时与旧值逐列相同。
- 身份链接器在读取已绑定来源时先解析规范 fixture，避免把别名和规范记录再次判为两个比赛。
- `fqp` 仅获新表 SELECT/INSERT，不授予 UPDATE/DELETE/TRUNCATE/DDL；触发器拒绝改写和删除。
- 本地固定样本、隔离 PostgreSQL、实际受限角色、并发环路、别名建立后的写入保护、迁移整笔回滚和 view 契约回归全通过；无跳过。
- 129 纳入固定 SHA 的无备份发布验证；部署只建空表，不写入线上别名数据。
- exact-head CI、独立只读复审、静态/安全/scope/budget 门禁通过。

## 范围排除
本任务不批量写入线上 967 组候选，不改赛果/赔率/赛季归属/预测，不训练模型。线上别名数据必须由下一批次依据新鲜只读清单、唯一性校验及受控事务单独实施。

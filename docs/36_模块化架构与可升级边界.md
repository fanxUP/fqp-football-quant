# 36. 当前模块化边界

## 实现入口

当前应用采用模块化单体：后端为 `routers/`、`services/` 与 `scripts/*_storage.py`；前端页面位于 `pages/`，静态路由位于 `App.tsx`。模块和面板定义来自最终注册表。

## 保留规则

1. 以 `configs/final_module_registry.yaml` 和 `configs/final_panel_registry.yaml` 识别模块及面板，不另建平行清单。原因：当前 UI 接口读取这两份注册表。
2. 修改模块前检查依赖、消费者和任务入口。原因：当前模块并不是可任意独立卸载的插件包。
3. 新数据源保留来源映射与快照，模型和票单使用已有存储边界。原因：跨层直接改变来源或历史数据会破坏追溯。
4. 维护菜单时同步注册表与实际路由/页面。原因：注册表控制导航展示，不能自动生成 React 组件或路由。
5. 数据库结构变更使用现有编号迁移并说明恢复方式。原因：当前目录是 `sql/*.sql`，不存在按模块强制分目录的执行器。
6. 模块关闭或删除前核对 required、safe_disable 和启用的依赖方，保留历史数据。原因：运行时状态接口会阻止不安全关闭，历史记录仍可能被复盘引用。
7. 模块变更说明影响、实际验证及回退边界。原因：现有代码没有通用 Module Contract 类或自动回滚机制。

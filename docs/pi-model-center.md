# Pi 模型接入中心

## 本次改造

固定使用官方 `@earendil-works/pi-ai@1.1.0`（MIT），服务器需 Node 24。统一模型目录、协议调用、API Key、Pi 实际支持的 OAuth 登录和凭据刷新。供应商预置来自本地锁定包，无需浏览器直接访问供应商 API。保留旧服务商代码、API 密钥、地址和代理绑定；旧的原生 Ollama 接入转用其 `/v1` 兼容接口，Anthropic 旧地址中的 `/v1` 自动规范为 SDK 服务根地址。

安装：

```sh
npm --prefix apps/model-bridge ci --ignore-scripts
npm --prefix apps/model-bridge run check
```

后端沿用现有 `FQP_PROVIDER_ENCRYPTION_KEY`，不要换成新密钥。迁移 106 仅增加 `auth_type`、`api_protocol`、`pi_credential_encrypted`；既有密钥保持原值。OAuth、附加云配置继续 Fernet 加密，所有 API 只返回固定密钥掩码和连接状态。Node 子进程不继承数据库、系统管理员或加密密钥；凭据仅通过标准输入/输出管道传递，没有公开 Node 端口、auth.json、浏览器本地存储或命令行明文。

## 使用

1. 搜索供应商，选择 API Key、供应商支持的账号登录或本地无密钥服务。
2. 搜索/选择 Pi 目录模型；API Key 接入可填写兼容服务模型 ID、服务地址和显式协议。
3. 保存后验证模型，通过后才能启用代理绑定。保存配置不自动开启任何代理。
4. 账号登录由使用者在供应商官网完成。支持设备码、选项和手动回调地址输入；远程服务器上的 127.0.0.1 回调不会自动访问使用者电脑。授权完成后复制浏览器最终回调 URL 回本页面即可。具体可用方式由供应商登录流程决定。
5. 断开接入删除已保存密钥/账号凭据并停用该供应商的所有代理绑定，不撤销供应商官网的授权；需要时在官网撤销。

Azure、Cloudflare、Vertex、Bedrock 等需要额外信息时，展开“兼容接口与附加配置”，按 Pi 官方供应商文档填写环境变量名称与值，如 `AZURE_OPENAI_BASE_URL`、`CLOUDFLARE_ACCOUNT_ID`、`GOOGLE_CLOUD_PROJECT`、`AWS_REGION`。凭据/环境值作为字面值传递，不执行 Pi CLI 的 `!command` 配置。此桥接使用显式 API Key 或已存 OAuth，不读取服务器其他账号的 ambient 云凭据；需要账号文件/云角色的配置应先确认此显式接入方式是否适用。

OAuth 会话绑定当前 FQP 登录 Cookie 的不可逆摘要，5 分钟到期，最多 4 个同时登录，每个供应商/系统会话仅一个。进程重启使正在进行的登录失效，已保存账号不受影响。当前服务器使用单个 API worker；增加多 worker 前需要把交互会话迁到共享服务或设置粘性路由。登录失败或配置在登录期间变化，不覆盖旧凭据。Token 刷新在独立凭据事务的供应商行锁下串行，不提交调用方的新闻/报告业务写入。最多 4 个独立凭据连接，避免嵌套使用应用连接池；刷新成功但生成失败仍保存新 Token。

本轮只实现与本地验证，不代表已上线。新增依赖发布须先在独立目录执行 npm ci 并验证 Node/Pi；备份现有数据库，对副本演练 106 和旧凭据保留，再走固定 SHA、测试证据与 readiness/认证接口验证。通用 deploy.sh 已把桥接 manifest/lockfile 纳入依赖变化拦截，要求完成专门的依赖发布准备。

106 的 down 为保留凭据的空操作。回退旧应用前停用 OAuth 配置、新增 Pi 供应商及相关代理绑定（保留所有加密字段），恢复原有服务地址/模型/验证状态后重新验证 API Key 接入；否则旧程序可能按原协议尝试新模型或错误使用保留的旧 API Key。Node 包独立于前端和 Python 依赖，可在确认没有调用后卸载。不要删除凭据列或替换加密密钥。

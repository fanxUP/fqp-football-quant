# 冷门研究与决策知识系统规格

## 1. 目标

在 FQP 现有官方数据、预测、投注、结算、复盘和回测链路上增加完整闭环：

```text
官方赛前赔率与模型预测
→ 官方赛果确认
→ 冷门量化识别
→ 证据收集与客观复盘
→ 用户实票与 Agent 虚拟投注分析
→ 日报、周报、月报
→ 联赛、球队、球员知识沉淀
→ 研究假设与回测验证
→ 版本化晋级为正式模型特征
```

目标用户是本地单用户。系统用于研究、复盘和模型改进，不替用户进行真实购买。
Agent 每日 500 元为独立虚拟资金，Agent 自主决定虚拟投注，不设置人工购买审批。

## 2. 核心口径

### 2.1 官方主数据

- 中国体育彩票官方比赛编号、业务日期、销售状态、玩法、固定奖金和赛果是主数据。
- 第三方信息只补充阵容、伤停、技术统计、天气、新闻和比赛事件。
- 官方源不可用时显示数据缺失，不得将第三方数据伪装为官方数据。

### 2.2 冷门定义

冷门只依据开赛前最后一个有效官方赔率快照和最终官方赛果计算，不按球队名气判断。

同一比赛、玩法、盘口、赔率快照内：

```text
raw_probability_i = 1 / odds_i
market_probability_i = raw_probability_i / sum(raw_probability)
actual_outcome_probability = market_probability_actual
surprise_bits = -log2(actual_outcome_probability)
```

默认等级（规则必须版本化、配置化）：

| 等级 | 实际结果去水概率 |
|---|---:|
| S 极端冷门 | `< 15%` |
| A 重大冷门 | `15%～22%` |
| B 一般冷门 | `22%～30%` |
| C 轻度冷门 | `30%～38%` |
| 非冷门 | `≥ 38%` |

另行记录“热门未打出”：赛前市场热门概率不低于 55%，最终结果不是热门方向。
赔率冷门、热门未打出、模型冷门和双重冷门必须分别标记，不能混成一个字段。

### 2.3 时间边界

- `business_date` 使用 Asia/Shanghai 业务日期。
- 所有用于识别和赛前模型复盘的赔率、预测、特征及证据必须早于 `kickoff_time`。
- `available_at` 晚于开赛时间的材料不能作为赛前预警证据。
- 开赛后的红牌、点球、比分和技术统计只能作为赛中转折或赛后解释。

### 2.4 AI 复盘口径

每场复盘分开保存：

1. 已验证事实；
2. 赛前可获得信号；
3. 赛中转折；
4. 分析推断；
5. 待验证假设；
6. 随机性因素；
7. 模型误差；
8. 可回测研究假设。

无证据内容不得写成事实。数据不足时必须明确显示“暂无充分证据”，不得强行归因。
AI 自然语言不得直接进入训练特征。

## 3. 完整范围

### P0 数据边界与基础设施

- 复用现有比赛、赔率、赛果、预测、特征、彩票、结算与报告实体。
- 增加模块配置、规则版本、运行记录和功能开关。
- 明确官方与辅助数据、赛前与赛后数据边界。

### P1 冷门识别

- 支持 HAD 和 HHAD，随后覆盖比分、半全场和总进球玩法。
- 保存开盘与临场赔率、实际结果概率、冷门等级、类型和检测规则版本。
- 检测任务幂等，同一比赛同一玩法同一规则版本不得重复写入。

### P2 API 与前端

- 冷门总览、列表、详情、筛选、分页和统计。
- 赔率变化、模型判断、用户实票、Agent 虚拟票和复盘状态联动。
- 页面具备加载、空、错误和数据不完整状态。

### P3 证据与复盘

- 保存来源、引用、发布时间、观测时间、可用时间、置信度和验证状态。
- 结构化生成复盘并运行质量校验。
- 外部数据缺失不得阻塞官方赛果结算和冷门基础识别。

### P4 日报、周报、月报

- 用户实票与 Agent 虚拟投注分开统计。
- 正确区分彩票、彩票选项、单关与串关。
- 提供收益、ROI、回撤、连亏、Brier、Log Loss、概率校准、冷门预警与分歧分析。
- 报告保存数据截止时间、规则版本、模型版本和提示词版本。

### P5 联赛、球队、球员知识库

- 结构化指标与自然语言总结分开保存。
- 所有画像具备有效期、样本窗口、样本量、置信度和来源。
- 教练、转会、伤愈、赛季和联赛变化触发过期或重新计算。

### P6 研究假设与模型反馈

- 复盘只生成 `research_only` 候选假设。
- 必须经过历史回测、时间切分样本外验证和模拟投注。
- 晋级过程版本化、可追踪、可回滚。
- 该审核只约束模型特征晋级，不约束 Agent 每日自主虚拟投注。

## 4. 成功标准

- 每场已确认赛果能锁定开赛前最后有效官方赔率并稳定计算冷门等级。
- 重复执行不产生重复事件、复盘或报告。
- 页面所有数字可追溯到赔率、预测、彩票和赛果记录。
- 赛后信息不会污染赛前预测或赛前预警。
- 用户与 Agent 的投入、返还和盈亏严格分离。
- 日报、周报和月报可自动生成并包含冷门研究章节。
- 联赛、球队和球员画像具备时间有效性，不保存无来源的永久结论。
- 只有验证通过的结构化研究假设能够进入正式特征候选。

## 6. 边界

### 始终执行

- 数据库变化使用顺序 SQL 迁移并提供 down 文件。
- 新任务记录运行状态、错误和输出引用。
- 新计算逻辑先写失败测试，再实现。
- 每个完整增量通过测试后使用中文 Commit Message 提交。

### 禁止执行

- 清空或替换现有数据库。
- 使用开赛后数据重算赛前预测。
- 将 AI 复盘文字直接作为模型特征。
- 将用户真实资金与 Agent 虚拟资金混合。
- 因辅助数据失败阻塞官方赛果结算。
- 为页面展示伪造冷门、赔率、赛果或知识数据。

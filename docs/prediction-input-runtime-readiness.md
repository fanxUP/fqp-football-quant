# P105 运行准备与启用门槛

本文是运行准备清单，不是生产切换脚本。本地默认特征任务已接入有界模式消费者，尚未生产发布。
当前没有新增服务、调度器、配置开关或供应商调用。

## CI 必须实际执行

现有CI先按数字顺序执行全部SQL，再初始化明确标记的隔离PG16副本。新增专门步骤运行
输入模式、109队列、110修订、旧消费者围栏与默认任务consumer五模块；pytest非零立即失败。
`scripts/ci/verify_prediction_input_results.py`继续检查实际JUnit case：五模块均有case、
没有跳过/错误/失败、没有重复身份、计数一致。缺数据库配置导致pytest跳过时，本步骤仍失败。
本地直接运行其他pytest保留原先可选数据库行为。后续全量coverage步骤继续执行。

隔离验证使用无外网/无暴露端口、限额tmpfs PostgreSQL与合成样本。纵向回归以
受限事实writer/输入consumer演练额度耗尽、过期降级、恢复、停售和重新开售；使用合成
profile只验证策略，不证明任何真实模型可用。`market_reference`始终非独立且不能直接建议。
本地执行工作流命令不等于GitHub真实CI；发布必须另有同一提交的真实CI结果。

## 数据库权限

生产必须重新核对实际角色、成员关系、对象owner及默认ACL，不能复制CI初始化脚本。

| 角色能力 | 需要的权限 | 原因 |
| --- | --- | --- |
| 迁移owner（NOLOGIN） | 拥有109/110新增表、序列、通知函数 | `SECURITY DEFINER`通知需以固定owner写头；运行账号不应改函数/结构 |
| 观测writer | 既有观测表SELECT/INSERT及对应序列USAGE | 事实与通知在一个事务；writer不需队列UPDATE权限 |
| 输入consumer | 头SELECT/UPDATE；进度SELECT/INSERT/UPDATE；回执、修订、cutoff和完整批次SELECT/INSERT；修订及批次序列USAGE | 领取行锁、进度更新与不可变结果提交；没有历史UPDATE/DELETE/TRUNCATE |
| 输入consumer读取依赖 | 官方比赛/市场/SP、精确球队映射、P104观测/cutoff/完整批次SELECT | 按当前上下文与确切batch作输入判断；不授予财务或凭据表权限 |
| 旧预测writer | 既有预测INSERT/序列及读取；头SELECT/UPDATE；官方比赛/SP行锁所需UPDATE权限 | 现有`FOR SHARE`/`FOR KEY SHARE`需相应权限；不得用表owner身份绕过审核 |
| 推荐reader | 既有业务SELECT及输入头SELECT | 每次从DB判断当前版本；无需领取或写修订 |

`FOR KEY SHARE`所需UPDATE可授予无实际更新用途的特定列，而不是开放整张官方表；
具体列与既有运行角色权限必须通过实际角色探针确认，不能假定生产已有权限。
通知函数固定`search_path=pg_catalog`、固定`public`对象并撤销PUBLIC EXECUTE；
schema-only复制若省略ACL会恢复默认授权，因此必须显式恢复撤权并验证。

## 事务与资源

- 当前读取/写围栏要求非autocommit、READ COMMITTED；读取后及时结束事务。防止旧MVCC快照冒充当前输入。
- 领取默认8、允许1–32；租约默认120秒、允许10–900；consumer key固定版本且一把key只对应一个玩法/profile契约。防止无限排队或重复定义消费者。
- 领取先commit；默认consumer在新事务一起提交cutoff、完整batch、修订和回执，显式API调用者也可单独提交cutoff；完成事务只做有界数据库写入。网络/训练/缓存/财务操作不得进入持头锁的回调。
- 旧预测围栏锁等待局部不超过500ms，保留更短配置；竞争只跳过该场/玩法。默认consumer每事务SET LOCAL statement<=5s/lock<=500ms并保留更严格值，生产还需实际角色和总任务资源验证。
- 109/110迁移lock_timeout=2秒、statement_timeout=15秒；消费者部署应另设明确statement/lock timeout与连接上限，按真实运行角色验证。当前只有隔离fixture的5秒/500ms证据。
- 不新增连接池或重试循环。后续受控调用复用既有任务/连接，限制单轮批量；租约失效或新版本只回滚/释放自己的claim，交下轮现有任务处理。
- 数据提交后才可刷新缓存；缓存失败不得撤销事实。执行建议前仍需DB当前读，缓存不提供有效性授权。

## 默认模式受控接线前的要求

1. 确定复用的现有任务及固定消费者契约，先显式、有限比赛/玩法调用；没有验证工件时只允许空profiles，结果诚实为市场参考/待核实。不能把旧模型挂成已消费P104。
2. 独立记录领取、完整batch/cutoff、修订、幂等回执和当前失效原因；观察新事件、失败/恢复、过期及停售/开球，不重复触发出票或财务。本地纵向fixture已验证实际任务入口（旧构建与追踪留存stub），真实生产任务与资源观测仍待发布。
3. 基础/增强独立模型启用须有P106的真实工件/特征/预处理兼容证明；P107完成消费者与界面证据迁移后再逐步扩大范围。P105可交付非独立回退，不能据此宣布预测质量提升。
4. 按实际连接总量、每轮处理数、耗时/锁等待、队列积压和RSS/SWAP做有限观测；超出边界先停用模式调用，不扩大超时或创建第二套队列。

## 生产发布与恢复门槛（尚未执行）

- 同一候选的真实GitHub CI、增量独立审查、范围/安全/迁移核验通过后才进入发布。
- 新鲜只读盘点当前提交、迁移账本、角色、事务、资源；人工保存匹配的schema、必要数据、序列、ACL与配置恢复材料，并在独立副本真实恢复核对。旧03/04固定样本证据不能替代生产恢复。
- 迁移暂停受影响任务，确认没有运行中的消费/长事务；应用109/110并验证对象、owner、触发器、撤权和实际角色探针。任一步失败就回滚当前事务并停止切换，不自动提高超时。
- 回退停止新增模式调用，保留109/110事实/队列/修订/回执。非空down明确拒绝，不能清空历史。部署器在任何109/110应用尝试后失败时，恢复旧代码但保持backend、scheduler、worker和nginx停止；不能自动启动尚未证明具备输入失效检查的旧版本。运维者须先部署兼容版本或验证独立建议停用门禁，再人工恢复服务。
- 部署和受控启用需具体生产变更授权；完成后核对代码一致、健康、角色与队列/历史边界。此文不授权生产操作。

## 默认任务接线（P105/06，本地证据）

`feature_snapshot_build.run` 在旧特征构建前调用 `drain_prediction_input_updates`，即使旧构建无可处理比赛也消费已有队列。dry-run不借用consumer连接或消费队列（既有任务追踪仍访问数据库）；不新增调度。固定 `observed-readiness/spf/v1`、`observed-readiness/rqspf/v1`，默认各8项，显式match_id只处理该场。只有已有观测头的比赛参与；不会给历史比赛伪造观测。

领取先commit，新的事务捕获catalog声明的全部五条stream（含缺失），完整55字段batch、修订、回执一起commit；任一步失败三者一起回滚。superseded/lease/锁等待/statement超时计为deferred，意外异常计failed并让作业状态失败；错误只记录类型，避免凭据或SQL内容泄露。所有重试均交下一次现有任务。

开球/停售/取消无法合法构建时，109围栏内写 `not_actionable` 回执，无batch/cutoff/revision引用且明确不可建议；不是伪造的模式修订。新官方事件可重新排队，但旧回执始终不可执行。身份不明写 `awaiting_verification` 回执，同一当前版本最早60秒后由现有调用限批重新排队；这可发现不产生官方事件的别名修正。已结束比赛不再周期刷新。

默认consumer始终 `profiles=()`，有合法SP时仅市场参考，否则待核实，没有独立预测许可。旧模型和旧推荐链路继续使用旧输入加事件围栏，不能声称已使用P104或完成P106/P107。生产的角色授权、恢复、迁移和有限观测仍未执行。

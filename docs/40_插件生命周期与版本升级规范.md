# 40 插件生命周期与版本升级规范

## 1. 插件化范围

FQP 的插件不是随意运行第三方代码，而是受控扩展包。适合插件化的内容：

```text
新数据源采集器
新赔率转换方法
新模型实验
新前端面板
新报表模板
新传统足彩组合策略
新 Agent 工作流
```

不建议插件化的内容：

```text
资金出入金
用户认证核心
审计日志核心
官方数据主表写入逻辑
生产推荐发布闸门
```

## 2. 插件清单结构

```yaml
plugin_id: model.dixon_coles_v2
name: Dixon-Coles 修正版
type: model
module: model_research
version: 0.2.0
status: experimental
entrypoint: scripts/models/dixon_coles_v2.py
permissions:
  - model_research.run.experiment
dependencies:
  - feature_store >= 1.0.0
rollback:
  disable_flag: model_dixon_coles_v2_enabled
```

## 3. 插件生命周期

```text
draft         草稿，仅文档存在
registered    已注册，未启用
experimental  实验环境可用
staging       预发布验证
active        生产启用
deprecated    已弃用
removed       已移除
```

## 4. 升级流程

```text
1. 创建插件或模块变更任务
2. Codex 生成代码和测试
3. 本地测试通过
4. staging 数据回放
5. 回测验证
6. 人工审核
7. 灰度启用
8. 观察指标
9. 全量启用或回滚
```

## 5. 兼容性要求

插件升级不得破坏：

```text
旧 API 响应字段
旧数据库字段
旧报表模板
旧回测结果可复现性
旧模型版本可追溯性
```

破坏性变更必须升 MAJOR 版本，并写明迁移脚本。

## 6. 回滚要求

每个插件必须提供：

```text
关闭 feature flag
回退配置
数据库回滚说明
任务停止命令
前端面板隐藏方法
影响数据清理说明
```

## 7. 验收标准

1. 插件可单独注册。
2. 插件可单独启停。
3. 插件失败不影响核心推荐。
4. 插件有测试和回滚说明。
5. 插件进入生产前必须有回测报告。

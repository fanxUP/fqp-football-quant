# P105 输入模式选择

`prematch_feature_dataset.load_prediction_input_mode` 是 P104 显式消费试点的后续内部入口。
调用者传入确切 batch ID、同场同玩法的 `PredictionContext` 和有界 `InputProfile` 清单；
只从 P104 读取一次全部有解释字段，再比较每份模型输入条件。它不触发采集、训练、发布或默认调度。

## 模式和缺失

| 模式 | 条件 |
| --- | --- |
| `enhanced` | 增强档案满足输入版本、验证、工件、独立性和市场能力要求 |
| `basic` | 基础档案满足同样要求，允许不使用未公布/失败的增强字段 |
| `market_reference` | 无合格独立档案，但同场玩法有完整、有效 SP 与快照引用 |
| `awaiting_verification` | 没有合格独立输入，也没有完整市场参考 |

先考虑已批准 `live` 的输入档案，再考虑 `shadow` 研究档案；同组优先增强再基础，
最后保留调用方配置顺序。这表达运行偏好，不证明增强模型效果优于基础模型。
当前只支持既有 SPF/RQSPF 能力，不能把 1X2 分类器输出改名当让球结果。

档案列出有序特征、必需列、兼容 feature version、模型版本和 validation reference。
**必需字段缺失永不通过**。可选字段也必须符合为同一模型/预处理验证过的确切缺失组合；
默认只允许无缺失，不能用“有 imputer”推断任何缺失分布均已验证。
即使声明了缺失组合，所有模型字段都缺失时也不作为独立信号。
允许的缺失仍传 `None`，交由该模型原有、已验证的预处理处理；本入口不填均值、0 或常量。
事实状态非 `value` 均不变成数值，包括 confirmed_absent，避免把已确认无记录误当评分0。
真实0和False保留原值/类型。某模型条件不满足只排除该档案，不影响其他基础输入或比赛。

输入必须是 P104 对**当前决策时刻**重验新鲜度的完整批次返回值。
旧 as_of 即使带有相同 batch ID 也不能直接复用为当前 ready；向量、状态、snapshot 与 batch/cutoff
引用不一致时只降级，不强行补齐。跨比赛输入直接报错，避免把其他比赛的事实用于本场。
有效批次的返回结果保留 feature version 与完整字段状态，方便区分未公布、冲突、过期和未知。

## 销售与研究边界

`recommendation_eligible=true` 只表示可进入原有下游推荐检查，不是已批准发布、下单或存在正收益。
它另需官方身份已核实、销售/比赛/玩法开放、明确销售截止与开球均未到、完整有效SP、live独立输入。
停售、缺截止、改期、SP缺失、shadow等原因写入 `restrictions`，只限制本场本玩法的入口资格；
研究输入仍可显示。市场参考始终 `model_independent=false` 且不可进入独立推荐。

P104 runtime batch 本身要求开球前时点。开球后，显式读取入口不再调用该runtime读取器，
返回市场参考或待核实及研究限制；历史/赛后研究修订须使用后续专门契约，不能伪造赛前建议。
销售截止恰好到达即关闭资格，后续更新不恢复可执行入口。

## 信任与完成边界

档案必须来自内部受控配置，validation reference、artifact_ready、independent 与 rollout_mode
表示调用者已完成相应验证，不能暴露为前端自由填写参数，也不是签名或权限证明。
本批没有创建 P106 的工件注册中心，不验证磁盘内容，不让旧工件自动兼容 P104 新输入语义，
更没有把任何现有工件切换成 live。没有已核准档案时就如实市场参考/待核实。
Context的官方身份、市场状态与SP引用也必须由内部授权读取提供；本入口不证明历史映射/完整价格批次。

本批仅完成输入模式子切片；事实与待办同事务、租约重领、消费期间再次更新、旧建议按版本失效、
缓存失败隔离和持久研究修订仍属 P105 后续。全量模型/页面消费者迁移仍归 P107/P116。
未新增SQL、依赖或HTTP API；原训练/预测调度不因新增显式入口改变。

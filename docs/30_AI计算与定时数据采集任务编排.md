# 30. AI 计算与定时采集编排

## 现行规则

1. 以 `scripts/jobs/run_scheduler.py` 中的 APScheduler 注册和实际环境判断任务时间及是否启用。原因：`configs/ai_scheduled_jobs.yaml` 已标记为历史设计，不参与运行调度。
2. 赔率轮询遵循 `FQP_ODDS_DISPATCH_OWNER`，同一业务库避免双重所有者。原因：Scheduler 和官方 Worker 均保留调度分支。
3. 接入追踪的任务使用现有 `start_tracked_job/finish_tracked_job` 或调度审计包装，保留输入输出引用和错误。原因：任务运行状态与数据管线页面依赖 `ai_job_runs`。
4. 为已有依赖检查保留真实上游任务代码和成功状态。原因：`check_job_dependencies` 根据最近执行的 `completed/ok` 结果决定是否阻断。
5. 保存赔率历史和特征快照，将可用预测关联到实际输入。原因：赛后分析需要复现赛前信息。
6. 失败处理沿用对应任务的重试、启动恢复和错误记录，报告未覆盖的链路。原因：当前没有统一“失败三次通知 DevOps/Risk Agent”的执行机制。
7. 手动全量备份保持为显式运维操作。原因：`verify_backup.py` 不在自动调度注册中，不能按早期日程承诺每日备份。

运行观测入口包括 `/api/ops/pipeline`、`ai_job_runs` 与当前环境的 Scheduler/Worker 日志。

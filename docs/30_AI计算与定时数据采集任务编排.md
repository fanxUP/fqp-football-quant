# 30. AI 计算与定时数据采集任务编排

## 1. 目标

将官方赛程、官方赔率、官方赛果、球队/球员/伤停/天气/赛制博弈、多维特征、模型预测、推荐生成、赛后复盘全部任务化，并由 Codex 负责开发、维护和修复任务代码。

长期运行时采用：

```text
APScheduler / Celery Beat / Cron 负责按时间触发
Worker 负责真实执行
Codex Agent 负责生成、修改、测试、审查、修复、受控触发
```

## 3. AI 计算任务

AI 计算任务包括：

1. 赔率去水概率计算。
2. Poisson 比分矩阵。
3. Dixon-Coles 低比分修正。
4. 球队 Elo / 动态评级。
5. 球队/球员身价特征。
6. 首发阵容强度评分。
7. 伤停影响评分。
8. 天气旅行疲劳评分。
9. 战意与赛制博弈评分。
10. 模型委员会投票。
11. EV 与资金分配。
12. 错因归因。

## 4. 数据快照原则

所有赛前数据必须保存快照：

```text
官方赔率：不可覆盖，只能新增。
首发阵容：预测首发、官方首发、赛后实际首发分开。
伤停信息：每次更新新增快照。
天气信息：按球场经纬度和比赛时间保存 forecast snapshot。
特征总表：每次预测前生成 match_feature_snapshot。
模型预测：绑定 odds_snapshot_id 与 feature_snapshot_id。
```

## 5. 失败处理

任务失败不能静默跳过：

```text
失败1次：记录 warning，等待重试。
失败3次：升级 error，通知 DevOps Agent。
关键任务失败：触发 Risk Agent 熔断。
官方数据失败：禁止正式推荐。
模型任务失败：允许只展示赛程，不展示推荐。
复盘任务失败：不影响赛前推荐，但必须补跑。
```

## 6. 验收标准

- 每个任务有唯一 `job_name`。
- 每个任务有 `agent_owner`。
- 每个任务有超时时间、重试次数、失败动作。
- 每个任务写入 `job_runs`。
- 每个 AI 计算输出绑定输入快照。
- 关键任务失败能触发熔断。
- Codex 能根据失败日志生成修复任务。

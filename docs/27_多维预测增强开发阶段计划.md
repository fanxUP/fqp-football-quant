# 27 多维预测增强开发阶段计划

## 阶段 11：赛季与球队数据库建设

### 目标

建立赛季、赛事、球队、球队别名、积分榜、球队赛季画像数据层，为战意、身价、晋级、保级和赛制博弈提供基础。

### 开发任务

1. 新建 `seasons`、`competitions`、`competition_seasons`。
2. 新建 `teams`、`team_aliases`、`team_stadium_history`。
3. 新建 `season_standings_snapshots`。
4. 新建 `team_season_profiles`。
5. 建立球队名称映射后台。
6. 建立积分榜快照采集/导入任务。
7. 建立球队赛季画像更新任务。

### 输入数据

- 官方比赛主客队；
- 赛事名称；
- 第三方球队名称；
- 积分榜；
- 赛季规则；
- 球队基础资料；
- 球队身价聚合数据。

### 输出数据

- 可匹配的球队 ID；
- 赛事赛季 ID；
- 积分榜快照；
- 球队赛季画像；
- 争冠/保级/晋级压力评分。

### 验收标准

- 官方比赛球队映射成功率达到 95% 以上；
- 未映射球队进入人工校对列表；
- 积分榜快照可按时间回放；
- 球队赛季画像带 snapshot_time；
- 任意历史推荐可查到当时球队赛季画像。

---

## 阶段 12：球员身价与阵容数据库建设

### 目标

建立球员主数据、球员赛季画像、球队阵容快照，用于计算球队纸面实力、首发身价、替补深度和关键球员评分。

### 开发任务

1. 新建 `players`、`player_aliases`。
2. 新建 `player_season_profiles`。
3. 新建 `team_squad_snapshots`。
4. 实现球员身价导入和版本化。
5. 实现关键球员评分。
6. 实现球队身价聚合任务。
7. 实现替补深度评分。

### 输入数据

- 球员名单；
- 球员位置；
- 球员身价；
- 近期出场；
- 合同/转会状态；
- 球队阵容列表。

### 输出数据

- 球员赛季画像；
- 球队总身价；
- 理论前 11 身价；
- 替补深度；
- 关键球员评分。

### 验收标准

- 重点联赛球队阵容覆盖率达到 90% 以上；
- 身价缺失时不按 0 处理；
- 球员转队后能保留历史球队赛季画像；
- 关键球员评分可解释；
- 球队身价特征可进入比赛特征快照。

---

## 阶段 13：伤停与首发快照系统

### 目标

建立伤病、停赛、预测首发、官方首发、实际首发体系，使模型能识别真实战力变化。

### 开发任务

1. 新建 `player_availability_snapshots`。
2. 新建 `match_lineup_snapshots`。
3. 新建 `match_lineup_players`。
4. 实现伤停影响评分。
5. 实现阵容强度评分。
6. 实现轮换风险评分。
7. 实现赛前 48h/24h/6h/1h 首发时间线。
8. 赛后写入实际首发并复盘预测首发准确率。

### 输入数据

- 伤病公告；
- 停赛名单；
- 预测首发；
- 官方首发；
- 实际首发；
- 球员身价和近期出场。

### 输出数据

- 缺阵影响分；
- 阵容强度分；
- 轮换风险分；
- 首发确认状态；
- 阵容不确定性。

### 验收标准

- 首发预测和官方首发分开保存；
- 官方首发不能覆盖预测首发；
- 缺阵影响分能按位置和球员重要性解释；
- 首发未确认时推荐风险自动上调；
- 赛后能统计预测首发准确率。

---

## 阶段 14：球场地理、旅行与天气系统

### 目标

建立球场、坐标、旅行距离、休息天数、天气快照，提升对客场疲劳、天气影响和总进球不确定性的建模能力。

### 开发任务

1. 完善 `stadiums`。
2. 新建 `match_travel_features`。
3. 新建 `match_weather_snapshots`。
4. 实现经纬度校验。
5. 实现旅行距离和跨时区计算。
6. 实现休息天数和连续客场计算。
7. 接入天气 API 或历史天气导入。
8. 实现天气影响评分。

### 输入数据

- 球场经纬度；
- 比赛地点；
- 球队近期赛程；
- 天气预报；
- 历史天气；
- 海拔和时区。

### 输出数据

- 旅行疲劳分；
- 天气影响分；
- 节奏惩罚分；
- 进球期望调整；
- 天气不确定性。

### 验收标准

- 球场缺失时不得伪造天气；
- 天气按比赛时间和球场坐标保存；
- 天气预报更新必须保留快照；
- 旅行疲劳进入 match_feature_snapshots；
- 月报能评估天气/旅行特征贡献。

---

## 阶段 15：战意、晋级与赛制博弈系统

### 目标

量化战意、晋级压力、保级压力、争冠压力、避强队、保平、净胜球目标、提前晋级轮换等因素。

### 开发任务

1. 新建 `team_motivation_snapshots`。
2. 新建 `tournament_group_scenarios`。
3. 新建 `tournament_incentive_snapshots`。
4. 实现积分压力评分。
5. 实现小组赛场景模拟。
6. 实现不同结果下潜在排名计算。
7. 实现潜在对手和路径难度计算。
8. 实现避强队评分。
9. 将赛制风险接入风控熔断。

### 输入数据

- 当前积分榜；
- 剩余赛程；
- 排名规则；
- 淘汰赛对阵规则；
- 潜在对手强度；
- 小组赛同组比赛。

### 输出数据

- 战意评分；
- must_win / draw_enough；
- 已晋级/已出局；
- 避强队风险；
- 路径难度；
- 轮换风险。

### 验收标准

- 战意评分基于数据，不凭主观文本；
- 小组赛末轮能计算不同赛果路径；
- 避强队只作为风险和不确定性，不作为确定性结论；
- 高赛制博弈风险时强制降级推荐；
- 赛后能复盘赛制判断是否有效。

---

## 阶段 16：比赛多维特征快照与模型接入

### 目标

把赛季、球队、球员、首发、伤停、旅行、天气、战意、赛制博弈整合为统一特征快照，并接入模型、推荐和复盘。

### 开发任务

1. 新建 `match_feature_snapshots`。
2. 为 `model_predictions` 增加 `feature_snapshot_id`。
3. 为 `simulation_ticket_items` 增加 `feature_snapshot_id`。
4. 实现 `build_match_feature_snapshot.py`。
5. 实现数据完整度评分。
6. 实现不确定性评分。
7. 将特征快照接入模型委员会。
8. 将特征快照接入推荐解释页。
9. 将特征快照接入日报/月报。

### 输入数据

- 官方比赛；
- 官方赔率；
- 球队赛季画像；
- 球员身价；
- 伤停首发；
- 旅行天气；
- 战意赛制。

### 输出数据

- 特征快照；
- 数据完整度；
- 不确定性；
- 模型修正特征；
- 推荐解释材料；
- 赛后错因归因材料。

### 验收标准

- 每个正式推荐必须绑定特征快照；
- 特征快照不可覆盖；
- 推荐时只能使用当时已存在的数据；
- 赛后能重建推荐时所有特征；
- 月报能分析每类特征贡献；
- 数据完整度不足时触发熔断或只模拟。

# V3e / P08a：阵容与伤停二维证据

## 实现

- 比赛详情新增“阵容与伤停”标签。该面板与特征、预测独立读取、手动重试；按比赛 ID 隔离，首次读取失败时数量显示未知而非 0。失败保留同场最近成功数据，成功空响应清空，错误比赛或球队标识拒绝展示。
- 首发、替补、其他名单分别展示。来源类型标记为确认、预估、历史或未知；完整 11 人、来源、时间和快照/比赛/球队标识缺失时提示可靠首发证据不足。来源标记不代表平台独立认证，也不承诺实时更新。
- 球员可用原生按钮和键盘选择，展示位置、角色和名单身份。真实的 0 分值保留，缺失数值显示 —。未提供号码和真实坐标，不把 ID 或列表顺序当作球衣号码。
- 扩展现有 `GET /api/matches/{id}/detail`：阵容增加 snapshot_id、match_id、team_id、source、snapshot_time、collected_at；伤停增加 player_id、snapshot_id、source、snapshot_time、collected_at。新增 availability_scope=`latest_per_player_team`、availability_limit_per_team=20。兼容原有字段及旧服务返回。
- 伤停查询先按球队、球员选择最新记录（时间相同按 ID 排序），再筛选 injured/suspended/doubtful。已记录的恢复状态可排除旧伤停；没有恢复记录时无法推断健康。每队最多 20 条，不声称全量覆盖。
- 阵容采集器以 FQP_TIMEZONE（默认 Asia/Shanghai）的本地时钟写入不带时区的快照，历史记录无法仅凭字段确认时区。前端保留原始快照时间并标注“时区未记录”；明确带时区的快照转换北京时间。入库时间按现有 UTC 审计字段格式展示，且不等同源站发布时间或最后修改时间。
- 当前球队伤停情报不能重建某场历史比赛的赛前状态。当前阵容不会覆盖冻结特征、预测或回测证据。
- 抽屉增加完整证据入口、来源/类型/快照摘要，删除空伤停列表的健康肯定提示，并移除易被误认为球衣号码的名单序号；匿名球员显示姓名未知。

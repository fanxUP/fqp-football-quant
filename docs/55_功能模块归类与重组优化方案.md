# 55_功能模块归类与重组优化方案

## 1. 当前问题

现有功能已经覆盖数据采集、推荐、实票、复盘、模型、回测、传统足彩、模拟投注和 Codex Agent，但模块边界存在三类问题：

1. 导航入口重复定义：前端侧边栏、前端 `panelRegistry.ts`、`configs/final_panel_registry.yaml` 各自维护入口，容易出现缺项和命名不一致。
2. 能力层和页面层混在一起：赔率、模型解释、模拟投注、彩池优化等页面直接挂在导航里，但没有清晰说明它们服务于哪条主流程。
3. 模块依赖没有形成闭环：推荐、实票、复盘、回测都依赖官方比赛、赔率快照、特征快照和模型版本，但页面归类没有把这条证据链展示出来。

## 2. 重组原则

模块不按技术文件夹归类，而按个人长期使用的业务闭环归类：

```text
官方比赛与赔率
  -> 特征与模型
  -> 推荐与资金
  -> 实票执行
  -> 结算复盘
  -> 回测与模型迭代
```

页面可以多，但每个页面必须归属一个模块；每个模块必须服务一条明确链路；共享能力沉到模块内部，不再作为孤立入口重复出现。

## 3. 新模块分层

### 3.1 核心闭环

用于每天实际决策和复盘，默认启用，不建议禁用。

| 模块 | 页面 | 职责 |
|---|---|---|
| 官方数据核心 | 今日驾驶舱、比赛中心、赛事中心、赔率走势、系统监控 | 官方赛程、赔率、赛果、数据健康 |
| 推荐与资金核心 | 智能推荐 | 模型预测汇总、票单生成、预算与风控 |
| 投注中心 | 投注中心、复盘分析 | 模拟投注、实票记录、Agent 对抗、结算、执行偏差 |

### 3.2 研究优化

用于解释推荐质量和长期迭代，不直接替代生产推荐。

| 模块 | 页面 | 职责 |
|---|---|---|
| 多维赛前情报 | 深度分析 | 特征重要性、条件表现、解释分析 |
| 模型研究与回测 | 模型中心、策略回测 | 模型版本、训练窗口、回测任务、评估指标 |

### 3.3 策略实验

用于玩法扩展和模拟验证，不直接混入核心推荐闭环。

| 模块 | 页面 | 职责 |
|---|---|---|
| 传统足彩 | 足彩彩池 | 胜负彩、任选九、组合优化 |

### 3.4 运维设置

用于维护、配置和自动化，不参与普通决策链路。

| 模块 | 页面 | 职责 |
|---|---|---|
| 模块运行时 | 功能模块 | 模块启停、依赖、面板状态 |
| 本地配置 | 系统设置 | 预算、主题、备份、数据源、本地开关 |
| Codex 多 Agent | 智能代理 | 本地 Agent 任务、协作边界、自动维护 |

## 4. 页面衔接方式

```text
今日驾驶舱
  -> 比赛中心
    -> 赔率走势
    -> 深度分析
    -> 模型中心
      -> 智能推荐
        -> 投注中心
          -> 复盘分析
            -> 策略回测
```

传统足彩和彩池优化保留为独立策略实验入口；模拟投注、实票管理和对抗竞赛合并为“投注中心”，作为推荐之后、复盘之前的统一执行层。

## 5. 本次落地调整

1. 前端侧边栏改为从 `panelRegistry.ts` 生成，删除独立硬编码导航数组。
2. `panelRegistry.ts` 补齐 17 个实际页面入口，并增加四类模块分层。
3. `configs/final_module_registry.yaml` 与 `configs/final_panel_registry.yaml` 补齐缺失模块和页面。
4. 新增前端注册表一致性测试，约束面板不能引用不存在的模块，模块不能声明不存在的面板。
5. 后端新增 `/api/v1/modules` 与 `/api/v1/ui/panels`，运行时读取最终模块和面板注册表。
6. 前端侧边栏优先使用运行时面板接口，后端不可用时回退到静态注册表。
7. 模块启停从前端本地状态提升到 `/api/v1/modules/{module_code}/status`，并增加必需模块和依赖模块保护。
8. 将“模拟投注”“实票管理”“对抗竞赛”合并为“投注中心”一级入口，旧路由保留兼容访问。

## 6. 后续迁移任务

1. 给核心闭环页面增加跨页链接：比赛详情链接赔率、特征、预测、推荐、实票和复盘。
2. 清理旧的 `configs/module_registry.yaml` 与 `configs/panel_registry.yaml`，保留为历史兼容或迁移为最终注册表格式。
3. 将当前 `data/runtime/module_state.json` 的本地状态存储替换为数据库表，用于多用户或多进程部署。
4. 继续将投注中心从页面聚合升级为统一 `/api/v1/betting/*` 聚合接口，详见 `docs/56_投注中心模块合并设计方案.md`。

## 7. 导航层合并规则（2026-07-10）

导航层采用“业务入口 + 分组”的方式收敛复杂度，底层模块和页面路由仍保持独立：

```text
核心闭环
研究优化
策略实验
系统管理
  ├── 系统监控
  ├── 功能模块
  ├── 智能代理
  └── 系统设置
```

“系统监控”仍然可以读取官方数据健康指标，但在用户导航上属于系统管理；“智能代理”负责任务、Job、审核和审计，“功能模块”负责模块启停与依赖，“系统设置”负责本地个人配置，三者不合并底层职责。

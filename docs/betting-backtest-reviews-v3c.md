## 修改和原因

| 页面 | 原问题 | 本轮处理 |
|---|---|---|
| 彩票 | 切换日期/状态失败后可能显示旧查询的票和分页游标 | 查询按日期、状态重新挂载；控件留在父组件以保留焦点；迟到响应不更新新查询 |
| 彩票 | 无明确手动刷新；分页错误或坏金额可能继续进入展示 | 手动刷新和接收时间；完整统计、票面金额及游标校验；同查询失败保留成功页；重复游标提示刷新 |
| 回测 | 快速切换运行，旧详情或曲线可能覆盖新运行；详情错误用列表重试 | 详情/窗口请求分别编号并核对运行 ID；切换清空旧证据；详情、窗口、列表分别重试 |
| 回测 | 最近30条被标为全部回测；缺少筛选分页；概率0被默认值覆盖 | 区分已获取数与数据库总数；搜索/状态/口径筛选、每页10条；序列化时保留合法0概率 |
| 复盘 | 日报和玩法统计、错因和摘要分别被 Promise.all 绑定 | 每项独立读取和手动刷新；失败保留本查询上次成功数据，首次失败不假称无记录 |
| 复盘 | 结算日期使用 UTC 初始化；旧请求可能覆盖新日期金额 | 上海业务日期初始化；按日期隔离读取；数值校验，有限记录金额口径明确 |
| 归档 | 周月报只能点击行；归档日期切换可能沿用子组件旧状态 | 原生查看按钮可键盘操作；按归档 ID/日期重新挂载详情子组件；合法空日报清除旧详情 |

使用现有主题和 BusinessEvidence.css，控件至少44px，聚焦状态复用现有样式；没有新增依赖或三维场景。
ReadEvidenceStatus 描述 GET 接收时间，不把它当作源数据生成时间。历史日报/周月报/结算/错因采用手动刷新；回测列表可见时30秒刷新、隐藏暂停。回测详情和窗口手动读取，窗口数据不是逐日资金曲线。

## 保留的业务口径

- 投注台选号、串关、注数、赔率、预算、删除确认、退款与结算实现沿用现有代码。
- 彩票服务器完整统计与按归属统计不改；每次最多100张，游标追加按 ticketUid 去重。加载历史超过100张后自动刷新暂停；手动刷新明确重新读取首页。
- 回测策略、方法版本解释和上线门槛计算沿用现有代码；只修复表单中0概率被替换成0.35的问题。无新增写入接口。
- 日报的资金曲线、玩法走势、冻结研究指标及自动报告机制沿用现有代码；查询失败不与暂无数据混淆。
- 结算请求最多100笔，页面合计仅为当前返回记录，明确标注非全日汇总；周月归档最多12份，错因列表最多100条，与近7天摘要不同。
- 后端窗口接口可能以 HTTP 200 空图表表示“无法读取回测视图”，该已知错误形态现在明确报错；合法空图表仍是空数据。该接口未提供总点数上限，本轮不补造限制或覆盖率。

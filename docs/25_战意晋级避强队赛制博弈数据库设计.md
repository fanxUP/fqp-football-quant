# 25 战意晋级避强队赛制博弈数据库设计

## 1. 模块目标

本模块负责量化比赛动机、积分压力、晋级压力、保级压力、杯赛轮换、避强队、保平、净胜球目标等赛制博弈因素。

普通模型常常只看球队强弱，但在以下场景中会失效：

- 已提前晋级球队轮换；
- 小组赛末轮打平即可晋级；
- 赢球可能进入更强半区；
- 小组第一未必比小组第二路径好；
- 保级队战意强于中游队；
- 杯赛前强队联赛轮换；
- 必须刷净胜球的球队打法激进。

本模块必须基于积分、排名、赛程和淘汰赛路径计算，不允许纯主观判断。

## 2. team_motivation_snapshots：球队战意快照

字段：

- 当前排名；
- 当前积分；
- 剩余比赛数；
- 争冠压力；
- 欧战/晋级压力；
- 升级压力；
- 保级压力；
- 无欲无求评分；
- 必须赢球；
- 打平即可；
- 已提前晋级；
- 已出局；
- 需要净胜球；
- 德比动机；
- 复仇动机；
- 主帅压力；
- 最终战意评分；
- 战意原因 JSON。

## 3. motivation_score：战意评分

建议公式：

```text
motivation_score =
晋级/保级/争冠必要性 × 40%
排名收益/奖金/资格收益 × 15%
主场/德比/复仇因素 × 15%
未来赛程压力反向惩罚 × 20%
阵容投入迹象 × 10%
```

评分解释：

| 分数 | 说明 |
|---|---|
| 0-25 | 战意弱，可能轮换或保守 |
| 26-50 | 一般战意 |
| 51-75 | 战意较强 |
| 76-100 | 强战意，结果高度影响目标 |

## 4. tournament_group_scenarios：小组场景表

用于计算小组赛中各种赛果下的排名和晋级概率。

必须保存：

- 当前积分；
- 当前净胜球；
- 当前进球；
- 晋级概率；
- 小组第一概率；
- 小组第二概率；
- 出局概率；
- 打平是否足够；
- 是否必须赢；
- 净胜球目标；
- 场景 JSON。

场景 JSON 应包括：

```json
{
  "if_win": {"rank_range": [1,2], "qualify": true},
  "if_draw": {"rank_range": [2,3], "qualify_possible": true},
  "if_loss": {"rank_range": [3,4], "elimination_risk": 0.72}
}
```

## 5. tournament_incentive_snapshots：赛制激励快照

专门处理“避强队”“保平”“轮换”“小组排名路径”等问题。

字段：

- 当前小组排名；
- 晋级状态；
- 赢球后潜在排名；
- 打平后潜在排名；
- 输球后潜在排名；
- 不同结果下潜在对手；
- 不同结果下路径难度；
- 避强队评分；
- 消极比赛/保守风险评分；
- 晋级后轮换评分；
- 激励摘要。

## 6. avoid_strong_opponent_score：避强队评分

建议公式：

```text
avoid_strong_opponent_score =
小组排名可控性 × 25%
不同排名对手强度差 × 35%
当前晋级安全度 × 20%
净胜球/积分约束 × 10%
教练轮换倾向 × 10%
```

高分不等于球队一定“故意输”，只代表从赛制收益看存在非正常激励，系统应降低常规争胜假设，增加不确定性和轮换风险。

## 7. 场景示例

```text
主队已提前晋级。
如果赢球，大概率小组第一，下一轮可能遇到强队 A。
如果打平，大概率小组第二，进入相对较弱半区。
本场赢球的边际收益低，轮换概率高。
系统处理：降低主队进攻动机，提高平局/小胜/轮换风险，不作为让胜重仓依据。
```

## 8. 数据接入

需要数据：

- 小组积分榜；
- 排名规则；
- 剩余赛程；
- 对手实力评级；
- 淘汰赛对阵规则；
- 半区路径；
- 是否已提前晋级；
- 是否需要净胜球。

## 9. 风控规则

出现以下任一情况，推荐引擎必须提高风险：

1. 已提前晋级且下一场更重要；
2. 打平即可晋级；
3. 小组第一路径明显强于小组第二；
4. 已出局但战意难以判断；
5. 必须刷净胜球，进攻倾向过强；
6. 对手比赛同时进行，实时排名变化影响目标；
7. 排名规则复杂且数据不完整。

## 10. 验收标准

1. 小组赛比赛能生成小组场景快照。
2. 能判断是否 must_win、draw_enough、already_qualified、already_eliminated。
3. 能计算不同结果下潜在排名。
4. 能计算潜在对手和路径难度。
5. 避强队评分必须进入 `match_feature_snapshots`。
6. 赛制博弈结论必须可解释、可回溯。
7. 不确定时只能提高风险，不能断言球队一定放水。

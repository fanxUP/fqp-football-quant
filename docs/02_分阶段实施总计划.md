# 02_分阶段实施总计划

## 总体原则

项目必须按“先真实数据、再模型、再推荐、再复盘、再长期优化”的顺序开发。不能先做推荐页面，然后后补数据。任何推荐必须绑定赛前官方赔率快照、模型版本和风控状态。每日500元预算是风险上限，不是必须投入金额。

## 阶段0：合规边界与项目规则确认

### 目标
把系统从一开始定义为数据分析、模拟、复盘工具，不碰互联网售彩、代购、出票、收款。项目中所有文案、接口、页面、数据库字段都必须体现这个边界。

### 具体任务
1. 完成《合规与责任边界说明》。页面底部、推荐页、实票上传页、个人运行手册都必须展示“仅用于数据分析与复盘，不提供彩票销售”的提示。
2. 建立禁止功能清单：禁止在线支付、禁止出票接口、禁止代购彩票、禁止合买、禁止跟单群转化、禁止保证收益表达。
3. 定义数据优先级：官方赛程与官方玩法为最高优先级；第三方数据只补充球队信息、历史战绩、伤停、天气，不得创建官方未开售比赛。
4. 定义推荐术语：使用“模型方案、模拟票单、价值指数、风险等级、建议投入”，不使用“必中、稳赚、包红、内幕”。
5. 定义每日预算规则：500元为风险上限，系统可以建议0元、100元、300元或观望。

### 交付物
- docs/18_合规与责任博彩提示.md
- configs/recommendation_shutdown_rules.yaml
- 页面文案和 API 免责声明字段

### 验收标准
- 所有正式文案不出现保证盈利表达；
- 不存在支付、出票、合买接口；
- 官方源不可用时不能生成正式推荐；
- 推荐页必须显示模型版本、赔率快照时间、风险等级。

## 阶段1：官方数据中台

### 目标
稳定采集官方赛程、玩法、赔率、停售时间、赛果，并保存原始响应和快照。没有这个阶段，后面所有模型都没有可信基础。

### 具体任务
1. 采集官方赛程：业务日期、官方场次编号、联赛、主队、客队、开赛时间、停售时间、销售状态。
2. 采集官方玩法：胜平负、让球胜平负、比分、总进球、半全场、混合过关；记录是否开售、是否单关、让球数。
3. 采集赔率快照：每次抓取都新增记录，不覆盖历史；保存SP、选项、快照时间、raw_json、raw_hash。
4. 采集赛果：半场比分、全场比分、胜平负结果、让球结果、总进球、比分、半全场。
5. 数据源健康监控：成功率、延迟、异常、缺失场次、赔率字段为空等。
6. 任务调度：比赛前48小时每60分钟、24小时每30分钟、6小时每15分钟、2小时内每5-10分钟，停售前30分钟强制最终快照。

### 落地说明
- 官方数据采集失败时，不能静默切换第三方；
- raw_json 必须入库，便于追溯；
- 如果官方页面结构变化，采集任务必须报警并暂停推荐；
- 第三方数据只能进入 external_* 表，不能直接写入 official_matches。

### 交付物
- sql/01_core_official_schema.sql
- scripts/official_crawler_stub.py
- configs/data_sources.yaml
- ops/cron.example

### 验收标准
- 连续7天能保存每日官方赛程；
- 每场比赛至少保存早盘、午盘、临场、最终四类赔率快照；
- 任意推荐都能反查到 odds_snapshot_id；
- 官方源失败时生成 data_source_health 异常记录。

## 阶段2：数据治理与球队映射

### 目标
解决不同数据源中球队名、联赛名、时间、时区、比赛匹配不一致的问题。

### 具体任务
1. 建立 teams、team_aliases、leagues、league_aliases。
2. 建立官方比赛到第三方比赛的匹配规则：日期、主队别名、客队别名、开赛时间差、联赛相似度。
3. 建立人工校对后台：低置信度匹配进入待确认队列。
4. 建立数据完整度评分：官方字段完整度、第三方特征完整度、赔率快照数量、赛果完整度。
5. 建立异常标签：队名映射失败、联赛映射失败、时间冲突、赔率缺失、赛果重复。

### 验收标准
- 常见球队别名可以稳定映射；
- 匹配置信度低于阈值时不进入正式推荐；
- 数据完整度低于80%的比赛只允许模拟，不允许实票建议。

## 阶段3：论文依据库与模型复现基础

### 目标
让模型不是拍脑袋，而是每个模型都有论文依据、适用范围、输入输出、复现实验和回测指标。

### 核心论文路线
1. Maher Poisson：基础比分生成模型；
2. Dixon-Coles：低比分相关性与时间衰减；
3. Bivariate Poisson：双方进球相关性；
4. Shin 模型：赔率去水与内部信息假设；
5. Favourite-Longshot Bias：热门/冷门赔率偏差；
6. Kelly / Fractional Kelly：长期资金增长与回撤控制。

### 具体任务
1. 建立 research/papers.bib；
2. 建立 research/paper_to_model_mapping.md；
3. 建立 notebooks/01_odds_probability_conversion.ipynb；
4. 建立 notebooks/02_maher_poisson_replication.ipynb；
5. 建立 notebooks/03_dixon_coles_replication.ipynb；
6. 建立每篇论文的复现验收指标。

### 验收标准
- 每个生产模型必须关联 paper_key；
- 每个模型必须有训练窗口、预测窗口、特征版本；
- 模型上线前必须通过 walk-forward 回测；
- 不能用赛后数据污染赛前预测。

## 阶段4：市场概率与赔率博弈层

### 目标
把官方 SP 转换成市场概率，建立赔率价值判断与市场博弈指标。

### 具体任务
1. 实现 simple normalization、power method、Shin method 三种去水概率；
2. 记录 overround、converted_probability、method_params；
3. 计算官方市场概率、模型概率、概率差、EV、CLV；
4. 建立热门低赔压缩指数和冷门高赔噪声指数；
5. 建立赔率波动等级：轻微、中等、剧烈；
6. 若推荐后赔率大幅变化，票单自动失效或重新评估。

### 验收标准
- 同一赔率快照可输出多种去水概率；
- 赔率变化超过配置阈值时触发重算；
- 推荐票单能显示“推荐时SP”和“最终SP”的差异。

## 阶段5：比分生成与赛果概率模型

### 目标
使用进球模型生成比分矩阵，再从比分矩阵派生胜平负、让球胜平负、总进球、比分和半全场概率。

### 具体任务
1. 实现 Maher Poisson 基线模型；
2. 实现 Dixon-Coles 低比分修正；
3. 加入时间衰减，让近期比赛权重更高；
4. 按联赛训练 attack、defense、home advantage；
5. 生成 0:0 到 7:7 比分矩阵；
6. 从矩阵推导竞彩五大玩法概率；
7. 输出 Brier Score、Log Loss、校准曲线。

### 验收标准
- 每场比赛输出 expected_home_goals、expected_away_goals；
- 比分矩阵概率总和约等于1；
- 可由比分矩阵推导所有玩法概率；
- 与市场概率基线进行效果对比。

## 阶段6：模型委员会与不确定性惩罚

### 目标
避免单模型过度自信。多个模型共同投票，模型分歧大时降低资金或不推荐。

### 模型委员会
- 官方市场概率模型；
- Elo/Glicko 动态评级模型；
- Maher Poisson；
- Dixon-Coles；
- LightGBM 特征模型；
- 赔率变化模型；
- 平局风险模型；
- 让球风险模型。

### 不确定性来源
- 样本不足；
- 小联赛；
- 伤停数据缺失；
- 赔率剧烈波动；
- 模型间分歧；
- 历史校准差；
- 临场信息不足。

### 验收标准
- 每个推荐显示模型一致性；
- 高分歧比赛不得重仓；
- 不确定性惩罚后 EV 不足时不出实票建议。

## 阶段7：推荐引擎、资金管理与熔断

### 目标
在每日500元预算上限内，根据 EV、风险等级、模型一致性和赔率稳定性生成模拟票单。

### 资金池
- 主策略池：300元，单关/2串1，低到中风险；
- 价值池：100元，EV明显但波动略高；
- 防守池：50元，低风险、防守组合；
- 实验池：50元，比分、半全场、新模型，仅小额或模拟。

### 风控硬规则
1. 每日建议投入不得超过500元；
2. 单票不超过100元；
3. 单场暴露不超过150元；
4. 比分玩法不超过每日预算10%；
5. 3串1以上不超过每日预算20%；
6. 连亏3天降为防守模式；
7. 连亏7天只给模拟；
8. 官方源异常不出单；
9. 数据完整度低不出实票建议。

### 验收标准
- 每张票绑定 model_version_id 与 odds_snapshot_id；
- 每张票有策略池、建议金额、风险等级、预期收益、最大亏损；
- 熔断触发时系统输出原因，不生成正式实票建议。

## 阶段8：实票上传与赛后复盘

### 目标
支持用户线下自购后上传彩票照片，系统手动/OCR识别、绑定模型票单、自动结算并复盘偏差。

### 流程
上传照片 -> OCR/手动录入 -> 用户确认 -> 匹配官方比赛 -> 绑定推荐票单 -> 等待赛果 -> 自动结算 -> 日复盘。

### 偏差标签
- 完全一致；
- 未买模型票；
- 额外购买；
- 改选；
- 加倍；
- 降倍；
- 追单；
- 临场新增。

### 验收标准
- 实票账户和模拟账户分离；
- 用户偏离率可统计；
- 每张票保留原图；
- 结算可重算；
- 修改有审计日志。

## 阶段9：日报、周报、月报与错因归因

### 目标
把每日结果沉淀为可迭代信息，而不是只看红黑。

### 日报内容
- 今日官方比赛数量；
- 推荐票单数量；
- 建议投入、实际投入；
- 模拟盈亏、实票盈亏；
- 模型命中率；
- 用户偏离率；
- 风控是否触发；
- 明日策略建议。

### 周报内容
- 总投入、总返奖、ROI、最大回撤；
- 各玩法表现；
- 各联赛表现；
- 各赔率区间表现；
- 最差错误类型；
- 下周预算建议。

### 月报内容
- 资金曲线；
- 回撤曲线；
- 校准曲线；
- 模型版本对比；
- 策略池贡献；
- 是否调整主策略。

### 验收标准
- 每日自动生成复盘；
- 错误必须打标签；
- 报表可追溯到票单和赔率快照；
- 月报能输出明确的下月策略调整。

## 阶段10：传统足彩 14场 / 任九组合覆盖

### 目标
支持传统足彩研究，不与竞彩足球固定SP逻辑混用。

### 具体任务
1. 建立期号、14场比赛、赛程、赛果数据；
2. 计算每场 3/1/0 概率；
3. 建立冷门指数和公共热度代理；
4. 生成胆、拖、防守选项；
5. 在预算约束下压缩组合注数；
6. 蒙特卡洛模拟命中14、13、任九概率；
7. 输出组合成本、理论命中率、冷门覆盖率。

### 验收标准
- 14场组合可以导出；
- 任九可以从14场中自动筛选；
- 每套组合有注数、成本、覆盖率、冷门分布；
- 不能把固定SP的EV逻辑直接套到奖池型足彩。

## 阶段11：回测中心与模型评估

### 目标
验证模型是否长期有效，不能靠单日红黑判断。

### 回测维度
时间范围、联赛、玩法、赔率区间、EV区间、模型版本、风险等级、资金池、过关方式、快照时间。

### 指标
Brier Score、Log Loss、ROI、最大回撤、最长连亏、样本量、平均赔率、CLV、资金曲线。

### 防作弊规则
- 只能使用赛前数据；
- 训练集和预测集按时间切分；
- 不使用赛后评级预测过去；
- 不用最终赔率回测早盘策略；
- 每次回测保存参数和数据截止时间。

## 阶段12：个人长期运行与运维

### 目标
一台服务器或本地机器可以长期稳定运行。

### 任务
1. Docker 一键启动；
2. PostgreSQL 每日备份；
3. 赔率快照归档；
4. 任务失败报警；
5. 官方源异常报警；
6. 模型版本可回退；
7. 报表定时生成；
8. 每月数据清理和备份校验。

### 验收标准
- 连续30天稳定运行；
- 官方赛程采集成功率>=98%；
- 报表生成成功率>=99%；
- 数据库每日备份成功率=100%。

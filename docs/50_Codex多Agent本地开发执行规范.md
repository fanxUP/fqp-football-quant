# 50. Codex 开发执行规范

1. Codex 负责开发维护，常驻任务使用既有 Scheduler/Worker。原因：生产任务不能依赖聊天后台。
2. 任务先确认目标和文件范围，只在现有 `main` 工作树中按顺序开发，不新建任务分支或额外 worktree。原因：本项目只保留一个开发分支，避免并行实现带来的分支漂移与重复整合；强制规则见仓库根目录 `AGENTS.md`。
3. 模型、采集、UI、运维等分工按当前代码路径和任务授权约束。原因：旧的模型、容器和 Cron 目录约定不能代表现有实现。
4. 修改前保留已有差异，不要求开发工作树无条件干净。原因：用户可能已有尚未提交的工作；服务器发布入口的干净 main 要求仍单独适用。
5. 测试和构建按任务授权执行，交付列出真实结果。原因：计划运行或文件存在不能证明验证通过。
6. 数据迁移、推荐发布、资金、实票和模型激活遵守现有审核与明确授权。原因：这些操作可能改变业务记录或有效策略。
7. 任务结束记录影响、证据、未完成项及回退方式。原因：后续提交和部署需要清晰的交接材料。

通用流程见 [31 号规范](31_Codex开发工作流与提示词模板.md)，角色与审核见 [29 号规范](29_Codex%20Agent角色权限与职责边界.md)，运行入口见 [54 号规范](54_本机运行与DockerDesktop弃用说明.md)。

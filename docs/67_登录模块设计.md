# 67. 登录模块设计

## 1. 概述

为 FQP 系统添加 Session + Cookie 登录认证，保护系统在公网/内网部署时的访问安全。

**变更范围：**
- `FQP_AUTH_MODE=none` -> `session`（env 配置切换，默认仍保持 none 兼容现有开发流程）
- 新增后端 auth 模块：Redis session + FastAPI middleware + 登录路由
- 新增前端登录页 + AuthContext + 路由守卫

## 2. 后端设计

### 2.1 新增文件

```
apps/backend/src/
  auth.py                  # Session 管理 + auth middleware
  routers/auth_router.py   # /api/auth/login, /logout, /me
```

### 2.2 环境变量

```
FQP_AUTH_MODE=session        # none | session，默认 none
FQP_ADMIN_PASSWORD_HASH=     # bcrypt 哈希值
FQP_SESSION_TTL=86400        # session 有效期（秒），默认 24h
```

- `FQP_AUTH_MODE=none` 时，auth middleware 直接放行所有请求，不影响开发
- 切换为 `session` 时启用登录保护

### 2.3 Session 管理（auth.py）

| 功能 | 存储位置 | 说明 |
|------|---------|------|
| Session 创建 | Redis session:{id} | 创建时生成 UUID session_id，存入 {user: "admin", created_at: timestamp} |
| Session 校验 | Redis GET | middleware 从 cookie 取 session_id，查 Redis 验证 |
| Session 过期 | Redis TTL | FQP_SESSION_TTL 控制，默认 24h |
| Session 销毁 | Redis DEL | 登出时清除 |

Redis 项目已有（`REDIS_URL=redis://127.0.0.1:6379/0`）。

### 2.4 认证中间件

```
请求 -> Cookie 中有 session_id?
  [无] -> 请求 /api/auth/*? -> 放行（登录/登出不需要验证）
          请求其他 /api/*?  -> 401 Unauthorized
          请求静态资源?     -> 由前端路由守卫控制
  [有] -> Redis GET -> session 有效?
           [有效] -> 注入 request.state.user，放行
           [无效/过期] -> 清除 cookie，按无 session 处理
```

### 2.5 API 接口

| 方法 | 路径 | 请求体 | 响应 | 说明 |
|------|------|--------|------|------|
| POST | /api/auth/login | {"password": "..."} | {"ok": true, "user": "admin"} + Set-Cookie | 验证密码，创建 session |
| POST | /api/auth/logout | - | {"ok": true} + Clear-Cookie | 删除 session |
| GET  | /api/auth/me | - | {"user": "admin"} 或 401 | 当前登录状态 |

密码验证：比对 `FQP_ADMIN_PASSWORD_HASH`（bcrypt hash），不存数据库。

### 2.6 保护范围

- `/api/auth/*` - 永远放行（登录/登出）
- `/health` - 放行（健康检查）
- `/uploads/*` - 放行（已上传文件）
- 其他 `/api/*` - 受保护，需要有效 session
- 前端静态资源（assets, index.html）- 由前端路由守卫控制，后端不做限制

## 3. 前端设计

### 3.1 新增文件

```
apps/frontend/src/
  pages/LoginPage.tsx        # 登录页
  app/AuthContext.tsx         # 认证状态 + login/logout 方法
  app/ProtectedRoute.tsx      # 路由守卫组件
  shared/api/auth.ts          # API 调用封装
```

### 3.2 认证流程

```
App 启动 -> GET /api/auth/me
  [200] -> user = admin -> 正常渲染
  [401] -> user = null -> 渲染 LoginPage
```

### 3.3 路由守卫

```
<ProtectedRoute>
  [user = null] -> 跳转到 /login，记住当前路径用于登录后跳回
  [user 存在] -> 渲染子组件
```

### 3.4 登录页 UI

- 红黑科技风，匹配现有主题（`configs/ui_theme_red_black_tech.yaml`）
- 居中卡片式布局
- 标题 "FQP" + 副标题 "足球预测量化系统"
- 密码输入框（type=password）
- 登录按钮（hover 时发红光效果）
- 错误提示区域（密码错误时显示）
- 无注册功能（单用户系统）

### 3.5 Cookie 说明

- Cookie 名: `fqp_session`
- HttpOnly - JS 不可读，防 XSS
- SameSite=Lax - 同一站点请求带 cookie
- Secure - 仅 HTTPS（生产环境），开发环境 HTTP 也可
- Path=/ - 全站生效
- 登录后前端无需手动管理 token，浏览器自动处理

```
sequenceDiagram
    浏览器 -> 前端 React: 访问 /
    前端 React -> 后端 FastAPI: GET /api/auth/me
    后端 FastAPI -> Redis: GET session:{id}?
    Redis --> 后端 FastAPI: null（无session）
    后端 FastAPI --> 前端 React: 401
    前端 React -> 浏览器: 显示登录页
    浏览器 -> 前端 React: 输入密码，点登录
    前端 React -> 后端 FastAPI: POST /api/auth/login {password}
    后端 FastAPI -> 后端 FastAPI: bcrypt 验证
    后端 FastAPI -> Redis: SET session:{uuid} + TTL
    后端 FastAPI --> 前端 React: 200 + Set-Cookie
    前端 React -> 后端 FastAPI: GET /api/auth/me (带cookie)
    后端 FastAPI -> Redis: GET session:{id}? -> 有效
    后端 FastAPI --> 前端 React: 200 {user:"admin"}
    前端 React -> 浏览器: 渲染主应用
```

## 4. 错误处理

| 场景 | 后端返回 | 前端表现 |
|------|---------|---------|
| 密码错误 | 401 {"detail":"密码错误"} | 登录页显示红色错误提示 |
| Session 过期 | 401 | 前端 /auth/me 检测到后显示登录页 |
| 未登录访问 API | 401 | 前端路由守卫显示登录页 |
| Redis 不可用 | 500 | 返回 500，前端 toast 提示 |
| 重复登录 | 200（已有 session 则先删除旧的） | 正常跳转 |

## 5. 安全说明

- 密码以 bcrypt hash 存在 `.env.local` 中，不硬编码
- Session ID 使用 UUIDv4
- Session 存储在 Redis，支持 TTL 自动过期
- Cookie HttpOnly + SameSite=Lax 防 XSS/CSRF
- `FQP_AUTH_MODE=none` 可随时切回无认证模式，便于本地开发
- Redis 只监听 `127.0.0.1`，不暴露到外网

## 6. 与现有配置兼容

当前 `.env.local`：
```
FQP_AUTH_MODE=none          -> 改或不改都可以，none 时全部放行
```

auth middleware 读取 `FQP_AUTH_MODE`：
- `none`（默认）- 直接放行所有请求，不影响现有功能
- `session` - 启用认证检查

这样现有开发流程完全不受影响，只需要部署时改一个环境变量即可开启登录保护。

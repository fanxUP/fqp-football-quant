# 67. 登录与管理员密码

## 当前行为

系统使用单管理员密码、Redis Session 与 HttpOnly/SameSite=Lax Cookie。`FQP_AUTH_MODE` 默认 `session`；仅显式 `none` 可关闭认证。原因：遗漏配置时也要保护业务接口。

`/api/v1/*` 先改写为 `/api/*`，认证和路由看到同一路径。公开路径仍为 `/api/auth/`、`/health`、`/uploads` 的原有前缀；其余请求必须有有效会话。原因：兼容接口不能导致登录被拦截，也不能扩大公开业务范围。

## 密码存储与持久化

- `FQP_ADMIN_PASSWORD_HASH`：既有bcrypt哈希，仅在持久文件不存在时作为初始化密码。
- `FQP_ADMIN_PASSWORD_FILE`：可选的私密哈希文件路径；默认项目根目录 `.runtime/admin-password.hash`。已有文件后，每次验证都读取它，进程重启或镜像环境中的旧hash不会覆盖新密码。
- 保存时创建同目录0600临时文件，写入哈希、fsync，原子替换并同步目录；不修改`.env.local`及其他应用密钥。原因：避免截断配置和明文密码，也不依赖某台服务器的固定路径。
- 既有文件无效、不可读时拒绝认证；不自动恢复初始化密码。原因：存储故障不能悄悄启用旧密码。文件缺失仍走初始化流程，运维需保护和留存此文件。
- 密码至少4个字符，UTF-8最多72字节；沿用原下限，字节上限对应bcrypt边界。

Docker Desktop compose显式配置`/app/.runtime/admin-password.hash`，使用已有`runtime`命名卷。升级/重新创建容器时保留此卷；`docker compose down -v`会删除该持久状态及其他数据，不是常规升级命令。原生服务器使用默认项目`.runtime`或配置持久路径；发布与回退均需保留它。

回退到本次修复之前的代码时，旧代码只读取环境hash；若期间已改密，需在受控回退中将当前持久hash同步到旧版配置，否则旧密码可能重新生效。仅保留文件不足以让旧代码识别新密码。

首次改密前，既有环境hash继续工作；首次成功改密后，单独改环境hash不再重置密码。需恢复密码时，由主机管理员在维护窗口原子替换私密文件为新的合法bcrypt哈希，并保留0600权限，勿将密码或哈希提交Git。

## 接口与会话

| 方法 | 路径（也支持/api/v1前缀） | 行为 |
|---|---|---|
| POST | /api/auth/login | 验证密码，删除当前Cookie对应旧会话，创建新会话 |
| POST | /api/auth/logout | 删除会话及发布标记、清除Cookie |
| GET | /api/auth/me | 有效会话200，无会话401，发布版本变化409/deployment_changed |
| GET | /api/auth/release | 无缓存的发布版本标识 |
| POST | /api/auth/change-password | 核验旧密码，持久保存新hash后返回成功 |

会话键与发布标记都在`session:*` Redis ACL范围内，校验通过才续TTL；发布版本变化时拒绝原会话，要求重新登录。改密保持现有策略，不自动撤销其他已登录会话；本次没有添加全局会话撤销机制。

## 故障与验证

错误旧密码返回401，密码长度无效返回400，持久化失败返回脱敏500。原子替换前失败保留原文件；替换后若目录fsync报错，新文件可能已生效，需核实持久文件并使用新密码重试登录，不能仅按500认定未改密。

2026-10-26本地固定样本验证：两个前缀行为相同，匿名业务接口仍401；旧密码拒绝、新密码接受；新解释器携带原始环境hash仍只接受新密码；0600、替换失败清理和文件损坏拒绝认证均覆盖。隔离Linux Redis验证包含两个路径的真实ACL登录、发布标记与旧Cookie清理。测试不连接生产，未部署实际Docker应用。

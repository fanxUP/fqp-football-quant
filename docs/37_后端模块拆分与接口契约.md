# 37. 后端维护与接口边界

## 当前结构

| 层次 | 位置 |
| --- | --- |
| Uvicorn 入口与应用工厂 | `main.py`、`apps/backend/src/app.py` |
| 路由 | `apps/backend/src/routers/` |
| 业务服务 | `apps/backend/src/services/` |
| 数据访问 | `apps/backend/src/db.py`、`scripts/*_storage.py` |
| 调度与任务 | `scripts/jobs/`、`scripts/official_crawler_stub.py` |
| 数据迁移 | `sql/*.sql` |

## 保留规则

1. 沿用相关路由、服务和存储入口做局部修改。原因：当前不是统一 `modules/<name>/repository.py` 布局，新增平行目录会增加重复实现。
2. 接口变更检查现有调用者、类型及 OpenAPI 描述并同步适用文档。原因：文档契约与实际响应可能不同，消费者依赖实际字段和语义。
3. 跨模块调用先确认当前依赖，不引入无消费者的 Contract、事件总线或微服务。原因：现有实现直接复用 Python 函数，没有通用契约发现机制。
4. 模块禁用按 `routers/ui.py` 的能力和限制判断，不能承诺自动停止 API 或定时任务。原因：当前禁用主要写入运行状态并过滤面板，路由由应用工厂显式挂载。
5. 对依赖缺失、无数据和执行失败保留明确结果。原因：静默成功会误导上游任务及页面状态。
6. 变更说明兼容性、验证范围和回退方式。原因：当前没有强制六类模块版本号或每模块独立迁移的实现。

模块状态实现：`apps/backend/src/routers/ui.py`；当前接口装配：`apps/backend/src/app.py`。

# 37 后端模块拆分与接口契约

## 1. 后端工程目标

后端采用模块化单体优先，预留微服务拆分能力。第一阶段不要过早拆成几十个微服务，否则开发、部署、联调和数据一致性成本过高。建议采用：

```text
模块化单体 + 清晰领域边界 + 模块级数据库迁移 + 统一任务队列 + 统一事件总线
```

当数据量和团队规模扩大后，再把高负载模块拆出：

```text
crawler-service
feature-service
model-service
recommendation-service
backtest-service
agent-service
```

## 4. 模块接口分层

每个模块至少提供 5 类接口：

| 接口类型 | 说明 | 示例 |
|---|---|---|
| query | 查询接口 | 获取比赛特征快照 |
| command | 写入/触发接口 | 生成今日推荐 |
| job | 定时任务接口 | 每日构建特征 |
| event | 事件接口 | odds_snapshot_created |
| admin | 后台管理接口 | 启停模块、参数修改 |

## 5. 跨模块调用规范

后端禁止跨模块直接引用 repository。跨模块读取只能通过 Service Facade 或 Read View。

错误方式：

```python
from modules.official_data.repository import OfficialMatchRepository
```

推荐方式：

```python
from modules.official_data.contract import OfficialDataContract
```

## 7. 后端模块版本号

每个模块必须维护：

```text
module_name
module_version
schema_version
api_version
job_version
panel_version
```

版本号变更规则：

```text
PATCH：修 bug，不改接口和表结构
MINOR：新增接口或字段，兼容旧版本
MAJOR：破坏性改动，必须提供迁移说明
```

## 8. 后端验收标准

1. 任意模块可以关闭，不影响系统启动。
2. 模块依赖缺失时显示明确错误，不允许静默失败。
3. 模块 API 有 OpenAPI 定义。
4. 模块定时任务可单独启停。
5. 模块 SQL 可单独迁移和回滚。
6. 模块测试可单独运行。
7. 模块变更可由 Codex 独立处理。

# 46. 模块维护、关闭与删除边界

## 保留规则

1. 模块 ID、依赖、required 与 safe_disable 以最终模块注册表为准。原因：早期 16 模块清单和多套命名已不能反映当前分组。
2. 关闭模块通过现有状态接口处理依赖，不直接伪造启停成功。原因：`routers/ui.py` 会拒绝必需模块、不安全关闭和启用依赖方冲突。
3. 分别确认菜单隐藏、页面访问、API 和后台任务的实际效果。原因：当前禁用状态只直接影响模块状态与面板筛选，不自动停止所有执行入口。
4. 删除代码前核对导入、动态调用、任务、路由和测试消费者。原因：静态无引用不等于没有命令行或调度入口。
5. 代码清理保留历史表、票据、模型版本和审计记录；数据删除另按授权处理。原因：运行代码已退役仍可能需要查询历史结果。
6. 改动记录影响、验证限制和回退办法。原因：`remove_module_safe.py` 只是打印步骤的 dry-run，不会真正完成停任务、隐藏面板和归档。
7. 沿用现有单体维护边界，不强制增加无消费者的模块版本字段或插件层。原因：这些旧要求没有统一执行器，容易产生新的死代码。

当前注册表：`configs/final_module_registry.yaml`、`configs/final_panel_registry.yaml`；状态接口：`apps/backend/src/routers/ui.py`。

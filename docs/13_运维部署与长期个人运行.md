# 13. 运维部署与长期运行

运行入口见 [54 号规范](54_本机运行与DockerDesktop弃用说明.md)，原生步骤见 [本机手册](../ops/local/README_LOCAL_RUNTIME.md)。

## 运行规则

1. 按实际运行方式核对进程管理器、端口与数据位置。原因：原生栈使用 launchd，服务器发布脚本使用 systemd，本地容器探针使用独立卷。
2. 同一数据库只运行一套有效 Scheduler/Worker，并确认赔率调度所有权。原因：重复调度可能重复采集、结算或生成票据。
3. 调度时间和启用条件以 `run_scheduler.py`、`official_crawler_stub.py` 与实际环境为准。原因：早期固定日程表和历史 YAML 不参与当前调度。
4. 不把 `/health` 可响应当成全部业务正常；结合 `/health/ready`、任务记录和业务数据判断。原因：接口存活与数据新鲜度、依赖就绪不同。
5. 全量备份按需手动执行，分别记录归档校验与隔离恢复结果。原因：当前没有每日自动全量备份，未恢复不能声明可恢复。
6. 保留失败日志、备份记录和已有数据。原因：删除异常证据不会修复系统，也会妨碍定位故障。

## 故障处理规则

1. 官方赔率或预测证据不足时明确展示缺口，并遵守现有实时推荐查询门槛。原因：旧快照或无效预测不能代表当前可用推荐。
2. 进程反复异常时先查对应日志和依赖，不靠反复启动判断修复完成。原因：守护程序能重拉进程，但不能排除业务根因。
3. 数据库恢复前确认目标库、备份和回退步骤。原因：代码回滚不能恢复被覆盖或删除的数据。

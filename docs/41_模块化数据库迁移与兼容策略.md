# 41 模块化数据库迁移与兼容策略

## 1. 目标

数据库是长期系统最容易失控的部分。正式项目要求所有表结构按模块管理，支持升级、回滚、兼容、审计。

## 2. 迁移目录规范

```text
sql/migrations/
├── official_data/
│   ├── 001_init.sql
│   ├── 002_add_odds_snapshot_label.sql
│   └── rollback_002.sql
├── feature_store/
├── recommendation/
├── ticket_review/
├── model_committee/
└── agent_codex/
```

## 3. 迁移命名规范

```text
{version}_{action}_{target}.sql
```

示例：

```text
001_create_module_registry.sql
002_create_panel_registry.sql
003_add_feature_flag_to_panels.sql
rollback_003_add_feature_flag_to_panels.sql
```

## 4. 禁止操作

生产环境禁止直接：

```text
DROP TABLE
DROP COLUMN
ALTER COLUMN TYPE
TRUNCATE
覆盖历史快照
删除模型版本
删除赔率快照
```

确需破坏性变更时，必须：

```text
1. 创建新字段
2. 双写一段时间
3. 数据迁移校验
4. 切换读取字段
5. 再废弃旧字段
```

## 5. 模块元数据表

模块化新增：

```text
system_modules
module_versions
feature_flags
frontend_panels
module_permissions
module_dependencies
```

用于支撑模块启停、菜单生成、权限控制和 Codex 任务影响分析。

## 6. 数据兼容策略

所有 API 响应新增字段必须兼容旧客户端：

```text
新增字段允许
删除字段禁止
字段语义改变禁止
枚举值新增需要文档说明
```

## 7. 验收标准

1. 所有新增表有模块归属。
2. 所有迁移有执行记录。
3. 所有破坏性变更有替代方案。
4. 所有模块有 schema_version。
5. 回测结果可以复现旧版本。

# 41. 数据库迁移与兼容规则

## 当前实现

迁移位于根目录 `sql/`，文件形式为 `数字前缀_说明.sql`；部分回退文件在 `sql/down/`。原生入口为 `ops/local/apply_local_migrations.sh`，服务器入口为 `ops/server/migrate.py`。

## 保留规则

1. 新迁移沿用根目录数字前缀和现有执行顺序。原因：当前执行器扫描 `sql/*.sql`，不扫描旧设计中的模块子目录。
2. 不修改已经登记执行的迁移，用新迁移表达后续变更。原因：执行器通过 `local_schema_migrations` 的 SHA-256 校验和检查历史文件。
3. 执行前确认目标数据库、权限、兼容性和数据保存方式。原因：相同 SQL 在不同环境可能有不同的数据量、锁风险和权限。
4. 不绕过危险 SQL 审查；破坏性变更说明影响及明确恢复步骤。原因：`migration_guard.py` 只匹配部分危险语句，不能证明数据安全。
5. 回退方案按实际迁移提供；没有 down 文件时说明兼容前进或备份恢复路径。原因：当前仅少数迁移有 down SQL，服务器发布回退会保留兼容性迁移。
6. 使用服务器迁移器时不在迁移内自带事务边界。原因：`ops/server/migrate.py` 会拒绝 BEGIN/COMMIT/ROLLBACK 并自行管理事务。
7. 数据字段或 API 语义变化检查所有现有消费者，并记录迁移或兼容方式。原因：只允许新增、永不允许删除的旧规则不能表达实际受控升级。
8. 历史模型、快照、票据和审计记录的清理单独评估并按授权执行。原因：结构升级不等于获得删除业务数据的授权。

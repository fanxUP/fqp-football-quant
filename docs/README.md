## 文档的效力顺序

不同文档描述的对象不同。按以下顺序判断“系统现在是什么状态”：

1. **当前运行行为**：实际代码、有效配置、已应用迁移和运行结果。设计文档本身不能证明功能已经启用。
2. **操作规范**：涉及开发、数据、安全、部署时，采用对应的现行运维和交付文档。
3. **当前任务状态**：以 FQP 工作区计划目录 `/Volumes/Nas/FQP/plans/` 下最新的任务检查点和交付记录为准；检查记录日期、提交号和环境。该目录不属于 `code/` 仓库，不随 `docs/` 发布到 GitHub。
4. **产品方案与历史记录**：用于说明目标、决策背景和当时验收结果，不代表当前实现或当前进度。

如果资料冲突，先确认它描述的是目标、实现规则还是某次历史状态；不要把旧计划中的工期、状态或测试数量直接当作当前结论。

## 使用注意

- 不必从头读完整个目录。先按上面的任务路线选 2–4 份相关文档。
- `02`、`15`、`27`、`35`、`51` 是不同时间形成的规划视角；它们不是五份可相加的当前排期。
- `52` 是旧版 Docker Desktop 开发规范索引；当前本机入口见 `ops/local/README_LOCAL_RUNTIME.md` 和 `54`。
- 方案、验收记录和运行手册要分开读：方案说明想实现什么，验收记录说明某个提交/环境当时做了什么，运行手册说明操作边界。
- `docs/` 中的 PDF/DOCX、`superpowers/plans/` 和专题目录保留原始资料；查找不到时用文件名检索，不要另建重复目录。

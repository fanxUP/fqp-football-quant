# 34. 运行环境、安全审计与回退

## 环境与凭证

1. 操作前明确当前工作树、目标服务和数据库环境。原因：原生、服务器和容器环境的配置与数据不能混用。
2. 密钥只进入私密环境或受控凭证存储，不写入源码、文档、命令输出和日志。原因：供应商 API Key、数据库密码和会话信息可直接授予访问权限。
3. 生产操作使用所需的最小权限。原因：普通应用任务不需要数据库超级权限。

## 数据与审计

1. 不覆盖官方赔率历史，保留模型和特征证据。原因：预测、回测和票据需要可追溯输入。
2. 实票编辑或删除通过已授权的现有接口执行，保留审计。原因：当前存储层支持审计删除，不能用旧的一律禁删规则否定现有能力。
3. 不把真实敏感数据导入开发环境，不在日志公开凭证或票据访问地址。原因：开发诊断无需扩散私密数据。
4. 破坏性数据库操作和高风险任务按明确授权及现有审核边界执行。原因：迁移检查器只拦截部分危险 SQL，不能代替影响判断。
5. 记录实际操作者、命令、差异和结果，说明审计覆盖范围。原因：数据库审计只覆盖已接入的调用。

## 回退

1. 代码回退选用已知可用提交，并采用对应环境的构建、重启和验证步骤。原因：只切换 Git 提交不会自动替换前端产物或运行进程。
2. 数据库变更先说明可执行恢复方式，再做已授权的实施。原因：多数迁移没有 down 文件，当前发布回退保留兼容性迁移。
3. 手动全量备份分别记录归档校验与实际恢复，恢复演练仅使用显式空的 `fqp_restore_*` 数据库。原因：`verify_backup.py` 有该隔离限制，校验通过不等于恢复成功。
4. 模型或配置回退保留旧版本和已有输出，不静默重写历史推荐。原因：旧票单和复盘依赖当时的模型与配置。

相关入口：`ops/server/deploy.sh`、`ops/server/migrate.py`、`ops/local/apply_local_migrations.sh`、`scripts/jobs/verify_backup.py`。

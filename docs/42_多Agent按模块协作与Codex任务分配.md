# 42. 按模块分工与任务说明

角色名称和项目登记来自 `configs/agent_registry.yaml`；代码模块来自最终模块注册表。

## 保留规则

1. 任务明确目标、允许/禁止路径、输入、产物、验收和影响。原因：模块名称本身不足以限定实际修改范围。
2. 使用项目 Agent 记录时采用已登记身份；普通开发任务按当前授权分工。原因：早期按模块虚构的 Agent 名称不一定存在于注册表。
3. 修改前读取相关注册表、依赖、接口实现及适用迁移。原因：影响判断需要真实路径；当前依赖文件位于 `configs/module_dependencies.yaml`。
4. 多人或多 Agent 协作时避免同时写同一范围，并说明交接基线。原因：共享工作树中的改动会互相可见。
5. 高风险项目任务遵守已实现的审核闸门。原因：`orchestrator.py` 和 `human_review_gate.py` 对待审核状态有实际检查。
6. 交付列出执行结果与未验证项，测试按任务授权进行。原因：不能把“分给 QA”写成已运行验证。
7. 历史赔率、审计和票据操作遵循数据边界与授权。原因：角色分工不能赋予删除生产记录或绕过审核的权限。

任务模板：`templates/codex/general_task_prompt.md`；审核规则见 [29 号规范](29_Codex%20Agent角色权限与职责边界.md)。

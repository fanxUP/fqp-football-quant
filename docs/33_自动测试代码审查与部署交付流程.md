# 33. 自动测试、代码审查与部署交付流程

## 1. 目标

把 Codex 产出的代码纳入标准工程质量门禁，避免“能跑一次”的脚本进入长期系统。

## 2. 必跑测试

| 测试类型 | 内容 | 负责 Agent |
|---|---|---|
| Unit Test | 函数、模型、评分公式 | QA Agent |
| Integration Test | 采集-入库-特征-模型链路 | QA Agent |
| Data Quality Test | 缺失、重复、快照覆盖、异常值 | Data Agent + QA Agent |
| Backtest Leakage Test | 是否使用未来数据 | Backtest Agent |
| API Contract Test | OpenAPI 与实现一致 | QA Agent |
| Migration Test | SQL 前向/回滚 | DevOps Agent |
| Report Test | 日报周报月报生成 | Review Agent |

## 3. 不允许通过的情况

```text
覆盖官方赔率历史快照
推荐未绑定赛前快照
模型预测使用赛后数据
真实收益与模拟收益混淆
生产 SQL 无回滚方案
数据源失败时仍发布推荐
风控熔断被绕过
测试失败仍合并
```

## 4. CI 流程

```text
1. 安装依赖
2. 静态检查 ruff/mypy
3. 单元测试 pytest
4. 数据库迁移测试
5. API contract 测试
6. 样例任务 dry-run
7. 生成测试报告
8. Risk gate 检查
9. 人工审核
10. 合并部署
```

## 5. 部署策略

```text
开发环境：允许 Codex 自动修改和测试。
测试环境：允许 Codex 触发任务，但不得触发真实推荐。
生产环境：Codex 只可受控触发，所有 L4/L5 操作必须人工确认。
```

## 6. 回滚方案

每次发布必须提供：

```text
代码回滚命令
数据库回滚 SQL
任务暂停命令
上一个模型版本
上一个配置版本
恢复验证步骤
```

## 7. 验收标准

- 所有 Agent 提交都经过 QA Agent。
- 所有迁移都有回滚。
- 所有模型任务有样例输入输出。
- 所有定时任务支持 dry-run。
- 所有发布可在 15 分钟内回滚到上一版本。

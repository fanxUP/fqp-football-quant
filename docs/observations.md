# P104：来源观测与时间截面

本批为本地工程切片，未连接真实来源、未部署，不代表完整 P104 验收。

## 三份追加记录

复用 PostgreSQL、P101 身份/状态/来源家族和 P102 特征定义。`observation_streams`
定位某来源、比赛、数据域、业务对象；`observation_revisions` 保存事实的内容版本；
`observation_checks` 保存每次采集回执与有效期。版本与回执通过复合外键绑定到同一 stream。

`0`、`false`、未知和确认无记录互不替代。确认无记录必须附完整查询覆盖证据。
请求失败只追加失败回执，不把上次事实改成零。`source_observation` 表示已检查的来源响应，
例如一份天气预报，不保证预报将成为实际天气；候选与研究重建默认不作已知观测。

修改内容会追加修订，A→B→A 是三个修订。内容相同的刷新仅新增回执，原发布时间、
首次取得/核验/入库时刻与内容版本不变。未知发布时间保持 `NULL`。
过期状态由相应 cutoff 前最后一份成功回执决定，原始事实状态仍单独返回。

## 截止时刻与事务可见性

观测时间为 `TIMESTAMPTZ`；调用方必须提供 aware 时间，旧比赛时间须显式按生产者时区转换。
天气旧表的无时区比赛时间按北京时间解释，未批量改写旧时间列。
可用时刻至少为数据库入库时刻、首次取得/核验和已知发布时间的最大值；补传旧公告不会倒灌过去。
预报业务目标时间可在未来，不能用 `effective_at <= cutoff` 错误排除已知预报。

时间戳本身不能证明一个事务在当时已经提交。必须在原截止时刻、任何写入前捕获成对凭证：

```python
cutoff = capture_observation_cutoff(conn, streams=[{
    "match_id": match_id, "source_id": "open_meteo",
    "domain": "weather", "subject_key": "forecast",
}])
conn.commit()  # 由业务调用方提交；失败回滚
observation = load_observation_as_of(
    conn, match_id=match_id, source_id="open_meteo", domain="weather",
    subject_key="forecast", cutoff=cutoff,
)
```

每份 cutoff 显式声明 1–128 个 stream，按声明顺序在单条 SELECT 的 MVCC 视图中取得当时已提交、
已可用的 revision/latest check/freshness check ID，连缺失 stream 也固定为缺失。单行不可变
`observation_cutoffs` 保存 UUID、UTC 时间、研究策略、引用 JSON 与摘要；不复制事实值。
调用者提交前其他连接不可见。拒绝捕获自身已分配写事务，以免将自身未提交事实当已知。
只读角色只能使用已提交凭证，捕获需要 INSERT 权限。

读取仅按固定引用，不再持久依赖原生 `xid` / `pg_snapshot`，因此新写入、延迟提交、重启及
独立集群恢复都不能改变已保存选择。读取检查摘要、引用结构、stream/版本/回执对应关系、
可用时刻与研究策略；凭证缺失/损坏、引用丢失必须报错，不会替换成最新。
JSON 内引用没有普通 FK，必须保留这些读取校验；观测表的不可变触发器阻止正常应用删除引用目标。
SHA256 是完整性检查，不是授权签名，也不能防御可管理 schema 的恶意管理员。

**恢复契约：** 一致 pg_dump/备份须同时保留观测、凭证、批次及序列；仅导出截止时刻或部分表
不构成可重放备份。恢复后旧凭证继续引用旧 ID，新 cutoff 只在恢复后的库重新捕获。
独立集群逻辑恢复和正常重启由本地固定样本验证；实际 HA/PITR/磁盘满/断电恢复仍需目标环境证据。
第一批原生快照 API 从未提交部署，107 的初始定义在本地修订；不能把本文件当作已运行旧107环境的升级脚本。
已覆盖的旧表、未保存凭证的旧预测仍不声称可以精确重放；也不会自动生成凭证冒充过去。

## 完整特征批次

`feature_batch_storage` 复用 P102 `FEATURE_SCHEMA_VERSION` 和有序字段子集，
`store_feature_batch` 一次 INSERT 保存整个批次、原 cutoff 外键、builder 版本、字段、值/事实状态、
确切观测索引与摘要，由调用者事务提交。单行 JSON 明细与 complete 对外一起可见；
JSON 数字表示保持原序列化，避免 JSONB 的指数数字规范化导致摘要漂移。
引用索引使用 cutoff 声明顺序；缺失也有声明项，未知保留 NULL，0/false 仅来自有效 value。
数值/确认无记录需要对应兼容证据；具体数值变换由具名版本 builder 负责，引用本身不证明变换正确。
研究重建凭证不能发布为运行特征批次。

完整表示每个声明字段都有解释，包括未知，不是所有字段齐全、预测可执行或模型独立。
`running` / `partial` 是不可变的尝试记录；完成时追加一条完整记录，不提前更新 complete。
`load_feature_batch` 只按确切 ID 读 complete；当前查询 `load_latest_feature_batch` 只在同
schema/builder/有序字段清单内选择，按输入 cutoff 再按尝试 ID 排序，晚完成的旧 cutoff 不压过新输入。
它返回 `latest_complete` / `previous_complete` / `no_complete_batch` 及最近尝试信息。
前一 complete 中的旧值不自动获得当前新鲜度，也不代表模型可执行；P105 负责具体能力降级策略。
历史 run 必须留确切批次 ID，不以当前查询冒充旧 run。原全量 builder 和模型消费者尚待迁移。

## 天气入口兼容

`store_match_weather_snapshot` 在一次事务中追加观测，再写原最新天气投影，最后提交。
任一步失败整组回滚。天气构建在保存失败时返回 `has_weather=False`，不把未保存值送入本次构建。
现有 `get_weather_for_match` 仍为最新投影读取，**不具有历史时点保证**；模型历史输入要逐批迁移。
适配器未提供发布时间时保留未知；六小时有效期是 `open-meteo-weather/v1` 的本地保守策略，
不是供应商发布频率承诺。库不会开启来源、改变额度、绕过权限或发出 HTTP 请求。

## 写入、权限与恢复

底层 append/采集失败接口不提交，调用方必须使用显式事务并负责回滚；同一 stream 的写入由事务锁串行。
建议写事务采用 READ COMMITTED；更高隔离级别产生序列化/唯一冲突时由调用方处理，不隐蔽重试。
单份 canonical JSON 上限 64KiB，索引约束单 stream 的版本/回执查找；连接/锁/总时长由调用方约束。

新表无 PUBLIC 授权，部署前应给批准写入角色 SELECT/INSERT、观测和批次序列 USAGE，批准读取角色仅 SELECT。
数据库触发器拒绝 UPDATE/DELETE/TRUNCATE，包括旧事实被应用覆盖；DB owner/superuser 仍可管理结构，
不以此声称防御恶意管理员。新增事实 FK 会阻止删除仍被引用的比赛，清理/保留政策在后续迁移前复核。

迁移 107 仅新增表/索引/函数/触发器，不复制旧事实、不覆盖历史预测；部署前要审目标版本、
角色授权、来源留存许可、锁风险、完整引用备份恢复。down 仅在对应新增表全空时可执行（先108再107），
有观测后应用回退必须保留这些表，不能删除证据。新增公开 HTTP API 和第三方依赖均为零。

## P104/03：首发与伤停事务组

`player_observations` 直接复用同一 PostgreSQL、规范球员 ID 与观测入口：
`api_football / lineup|injuries / team:<规范球队ID>`。每队首发观测、旧头表和全部明细一起提交；
首发必须有11位唯一可识别球员，部分/未公布只留明确状态，不新增 confirmed 投影。
球员当前投影替换不累积旧名单；历史 cutoff 仍引用旧名单观测，不能从覆盖表伪造历史。
单方已公布可独立留存，另一方不会被补成已确认。此入口不证明球员当前注册资格或转会有效期（P108）。

每场伤停的两个球队观测、旧查询回执和球员明细一次提交；球员身份创建也加入该事务。
新响应更正时仅清理同场/同队/api-football 的旧投影，其他比赛和原始观测不删除。
来源事实留原报类型/原因，不把旧启发式伤停/身价/强度评分当来源实测值；旧投影分数的替代仍属后续工作。
底层旧 store 接口默认行为保留，组调用使用 `commit=False`，最终由 collector 一次提交/失败回滚。
两个 collector 在取得 HTTP 响应后才持有同一有界 DB 写事务锁，先协调共享新球员身份再获取 stream 锁，
避免重叠名单初次创建的键竞争/锁反序。锁期间不发 HTTP；每侧最多64球员/伤停每场128行。

**空响应与完整覆盖：** fixture injuries 校验明确 response 数组、已给出的结果数/分页是否完整；
错fixture、未知球队、重复/缺失ID和结构错误不能写完整回执。HTTP成功/空数组不构成来源覆盖许可：
当前来源目录 coverage 未核准，真实 collector 不提供 `coverage_evidence`，空侧事实 UNKNOWN，
有原报记录的侧留 VALUE 但不宣称覆盖完整。旧 `get_injury_observation_for_match` 对新 partial 回执返回 None，
避免其计数0被现有构建器当完整零伤停。仅内部可信覆盖证据参数才可产生 CONFIRMED_ABSENT；
本地固定证据只用于回归，不是启用真实来源或给来源核准覆盖的配置开关。
旧无此版本标记的回执仍按旧读兼容，它们没有原 cutoff，不能声称精确重放。

取得/核验为响应完成后的 aware UTC，旧 `snapshot_time` 明确归北京时间无时区；未知发布时间仍NULL。
失败只追加安全采集状态，不写零/覆盖事实；失败回执本身写失败会报告 `failure_receipt_unavailable`。
30分钟查询新鲜度是本地节流策略，成功未知/未公布也可减少重复请求，并非“完整覆盖”或来源SLA。
同一窗口全为新鲜回执时连赛程发现请求也跳过；过期或失败不再永久跳过更正，所有HTTP仍经P103共用额度。
为避免误称覆盖，任务新增 `matches_recently_checked`，旧 `matches_already_complete/observed` 保留但不以新鲜度推断。
首发报告 waiting/降级，伤停报告 coverage_unverified；其他比赛和模块继续处理。

权限：观测依然只追加；组写角色另需规范球员/名单头的SELECT/INSERT/UPDATE、名单明细和伤停当前投影的限定
SELECT/INSERT/UPDATE/DELETE、队伍回执SELECT/INSERT以及相关序列USAGE；不需金融/凭据表权限。
应用的谓词限定删除范围，部署前仍需核验目标角色，不把本地测试角色视为生产授权。

## P104/04：字段权威与冲突归并

`observation_resolution.resolve_observed_field` 从同一不可变 cutoff 的确切 selection 读取，
不查询最新投影、不写表、不提交事务、不请求来源。调用者须先通过既有访问与留存许可；
来源目录、内部 policy 参数和此只读函数均不是访问控制，不能开放给终端用户自定优先级。

单一 `data_catalog.field_resolution` 声明 `observation-fields/v1`：

| 字段 | 当前准入来源 | 取值 | 时效上限 |
| --- | --- | --- | --- |
| weather.temperature_2m | open_meteo | 原始摄氏温度 | 6小时 |
| lineup.starters | api_football | 11名首发规范球员ID的有序集合 | 30分钟 |
| injuries.complete_report | api_football | 完整覆盖的原报球员/类型/原因 | 30分钟 |

rank数字越小优先，**仅针对对应字段**；当前每个字段只准一个已存在适配器来源，
没有启用新来源，也没有声称已核准真实覆盖/留存。多源、转载和竞争由固定样本验证。
不将新闻API自动变为首发事实源，不使用旧身价/影响分数，不推断转会归属、注册资格或出场分钟。
温度 v1 仅接收有限非布尔数值且在[-100,70]摄氏度的输入校验范围，数值0/0.0/-0.0视为同值；
不读取派生天气评分。天气必须有明确业务目标 effective_at，不同目标时刻不当同一声明，
未来比赛预报不会因 effective_at 晚于 cutoff 被排除。队伍名单必须属于对应规范 team stream。

每个准入来源都必须在 cutoff 显式声明，即使当时缺失；不能为得到某答案而省略较高等级来源。
调用入口按match/domain/subject过滤但返回原cutoff索引，不将另一队或比赛的索引冒充本队证据。
有值、确认无记录与未知/未公布/不覆盖/不适用/冲突/过期分开。
完整伤停字段同时要求 `coverage_complete=true` 与有界可信 `coverage_evidence` 引用，
空无证据仍unknown；非空但覆盖未核准仍保留原记录但不能发布为完整名单。
只有原事实 CONFIRMED_ABSENT 且有覆盖证据时结果才confirmed_absent，值保持NULL，不填0/空数组。
**覆盖参数来自可信适配器准入，不是自由字符串可以证明现实完整性；实际许可仍单独审核。**

新鲜度按**原cutoff**与固定回执的最后成功 acquired_at + 字段上限、来源 valid_until 中较早者比较；
边界即过期，没有valid_until也不无限有效。同内容成功刷新可以更新该回执时效，不能改旧凭证。
失败/额度耗尽不会重置成功时钟；仍有效旧事实可以使用但候选中披露最近采集状态，过期仍stale。
抓取时间较近不自动胜过等级更高的来源，未知发布时间不会补成抓取时间。

新鲜 asserted 候选的最高等级全部一致才选值；同级不同值/无记录声明或来源本身conflict，
结果为conflict/NULL且无selected索引，不投票、不平均、不用转载数量决定。
低等级可作缺失/过期的候补，但原因保留；较高等级可压过低等级异议，异议索引仍披露。
相同家族的多个引用全部保留，但 `selected_family_count` 只按冻结family去重，
它是目录家族数量，不是独立调查数量、信心分数或真实性证明。同源互相矛盾仍保留冲突。

返回完整policy快照/SHA、cutoffID/UTC时刻、候选来源/冻结家族/修订与回执ID/原内容摘要、
规范化字段值、状态、排除原因、selected与disagreement索引；原大段响应仍只在观测库。
结果只是可解释的来源声明选择，不是模型输入可用性或准确率证明。
需要重放决策的调用者须保留返回policy快照，并显式传入同一快照；默认目录升级后的策略摘要不同，
不能冒充旧决策。当前全量builder/模型尚未调用此入口，批次仍按旧契约，无策略持久化/模型工件完成之说。

**家族生命周期：** 旧cutoff读取按其冻结family与原stream比对，目录改家族名不会重写历史或使旧读失效。
新写入和新cutoff若发现既有stream family与当前目录不同均报错，不能静默伪装成缺失或新的独立票。
变更家族需要明确迁移和复核；退役来源在目录保留身份tombstone，不能删除历史ID。
policy快照是完整性与可重放材料，不是签名、权限或防御恶意数据库管理员。
# P104/05：显式消费试点

现有构建任务模块新增 `build_observed_feature_batch`，共享模型数据模块新增
`load_observed_feature_input`。两者需调用者明确传入，不改变默认调度、训练或预测。
当前不是全量消费者迁移，也不授权已有模型工件直接使用新输入。

- 调用者先捕获天气、双队名单与伤停的同一 cutoff（包含缺失），再提供规范主客队 ID
  和带时区 kickoff 上下文；这些是留存的明确声明，不是历史映射或赛程观测证明。
- 一次发布既有 55 字段。温度须来自同一 kickoff 目标，首发确认须完整 11 人；
  其余无时点派生的字段明确 unknown，空引用和原因不充当来源证据。
  伤停规则决策保留，但完整空报告也不自动推出关键球员数量或影响评分。
- 既有 batch JSON 增加可选、有界 `derivation`，无新 SQL。旧三键格式不变；
  具名试点读取必须用原 cutoff、原策略及原上下文复算，按规范化 JSON 保留
  布尔/数值类型区别，不能从最新旧投影补齐。
  不支持的旧批次返回 `unsupported_batch_contract`，没有完整批次则明确返回原因。
- 读取 exact batch ID，预测时间必须带时区、在 cutoff 后且 kickoff 前。
  逐字段检查预测时是否过期；不重写原批次、不使用后来取得的刷新回执。
  必需字段缺失返回 `insufficient_inputs`，可选字段未知保持 None。
- 有序模型列和必需列由调用者明确声明。`ready` 只表示满足这份输入要求；
  新 `feature_version` 故意不在旧工件兼容列表，不能伪称已有工件经新数据验证。
  当前只用本地固定样本贯通既有分类器数值边界，没有训练/效果提升或 P106 run 证明。

# 赛前特征、模型输入与预测口径

P102 三批实现的当前说明。代码已分批做本地固定样本验证，完整 A102/发布仍须独立审查、适用目标库验证与发布检查；不代表预测效果或收益得到验证。

## 唯一字段与读取边界

`scripts/feature_schema.py` 保持现有 55 列的唯一顺序，写入 64 列、读取 65 列（含 ID 和既有元数据）；不增加数据库列。每个模型只使用工件保存的有序子集，不能因补齐存储就自动增加输入。0/false 与 None 分开；未知字段不自动持久化。

公共读回要求明确 `as_of`，快照不晚于预测时间且严格早于开赛；相同时间用 ID 降序。现有业务表使用上海本地无时区时间，拒绝将带时区值悄悄去掉时区。这还不是 P104 的可用时间、观测修订和完整批次契约。历史快照与预测不重写。

## 新旧语义分开

| 输入 schema | 可配快照 | 当前处理 |
|---|---|---|
| `legacy-enriched/v1` | `v1_basic`、`v2_enriched`、`v3_upset_risk` | 仅用于显式旧版本工件和旧快照；不改名为真实身价/实力 |
| `observed-form/v2` | `v4_observed_form` | 新构建、共享影子训练和解释模型使用的版本 |

新快照中 `home/away_team_market_value` 和 `team_market_value_ratio` 为空：没有估值来源、币种和估值日期，因此不产生身价数值。市场隐含概率保留在 `raw_feature_refs.odds_implied`；不再冒充身价、进攻或防守。

沿用已有 `attack_strength_score` 列保存近 10 场可用官方历史的场均进球，`defense_strength_score` 保存场均失球（低为好）；字段结构没有改名，但含义换版。查询只接收 final/confirmed、双方非负且非空的比分。没有历史就留空。raw refs 保存双方实际场数、进失球、窗口/来源和定义；解释标签明确“场均进球/失球”。这不是完整所有赛事覆盖、对手调整或当前球员阵容的实力评级；P108/P111/P112 继续负责球员事实与动态模型。

新共享训练与解释查询只选 v4，不将两种单位/分布混合训练。旧 schema 只能配旧快照，新 schema 只能配 v4；没有版本的旧工件拒绝加载，走现有市场回退，不投票。不会自动重训、激活、重标工件或补造历史 v4 数据。解释页在新版本样本不足时返回已有样本不足状态。

## 工件与预处理

十一影子分类器统一要求 `snapshot-columns/v1`、合法且唯一的已知有序子集、匹配的 schema/快照版本；工件 `n_features_in_` 必须等于子集宽度，有 `feature_names_in_` 时顺序也必须完全一致。训练保存相同元数据并验证实际拟合宽度，再沿用现有 shadow 保存流程。

None、非法或非有限数值统一为 NaN，0/false 保持 0；各分类器使用既有训练折预处理，不使用未来验证集估算填充值。XGBoost 训练与解释统一保留原生 NaN；SHAP 明细 `feature_value` 缺失为 JSON null，页面显示“缺失”，真实 0 保留。不存在签名或不可变训练清单保证；P106 负责这些能力。

## 玩法能力

唯一声明在 `scripts/model_signal_policy.py`，两个预测写入入口共同使用。unsupported 玩法没有该模型的新预测行，不改写历史。

| 模型 | 普通胜平负 spf | 让球 rqspf | 比分/总进球 bf/zjq | 半全场 bqc |
|---|---|---|---|---|
| 市场基线 | 是 | 是（按盘口赔率引用） | 是 | 是 |
| Maher / Dixon-Coles | 是 | 有限整数让球且历史进球率有效时投影；未训练只留市场回退 | 是（比分矩阵） | 暂停 |
| Bivariate / Negative binomial | 是 | 同样需要有效盘口和历史进球率/对应拟合参数 | 本轮未接入 | 暂停 |
| Elo/Glicko/Bayesian form/十一分类器 | 是 | 不支持 | 不支持 | 不支持 |

0 让球是有效值；缺失、非法、非有限、非整数盘口只保留 rqspf 市场基线。不能用让球赔率反推普通进球率后再次让球；没有历史拟合时，支持的比分模型在该盘口保留市场回退且无独立票。半场×全场的旧乘积公式已撤下，bqc 只保留市场基线，合法联合模型由 P113 评估。既有 BF/ZJQ 的可用官方选项归一方式保留；市场完整批次由 P104 负责。

## 分歧不等于可信度

计算诊断前，先校验各 active 且支持该玩法的概率分布。只有实际成功、非 shadow、非市场回退、模式为 live 的信号进入诊断/委员会权重。

- Maher/DC/Bivariate/Negative-binomial 同属进球率家族；Elo/Glicko 同属历史评级；Bayesian form 属历史赛果；十一分类器属快照分类器家族。
- 每家族内部先取均值，再在家族之间均权计算标准差；少于两家族，`uncertainty_score` 和 `model_std` 为 null。
- 家族是保守来源分组，不是证明统计独立；现有 `model_independent` 只表示该信号不是市场回退。诊断 JSON 明确 `family_disagreement_not_confidence`。
- 委员会保留各模型行，但同家族有效模型平分该家族总权重 1；数量不代表额外独立来源。计算失败不能保留独立标志。
- 未做候选外样本校准前，新预测的 confidence_score、risk_score、上下界均为 null；不会用 1−3σ 冒充命中把握或以 ±2σ 生成统计置信区间。P114 拥有真实校准与融合评估。

现有预测 API/TypeScript 允许置信度为空，二维指标组件以“—”显示缺失。推荐编排和票项参数保留 confidence/risk 的 null；已有 LiveRecommendation.confidence 与投注依据类型支持 null，页面显示“未校准”，不画0%的量尺、不算高置信强信号。只读推荐 API 的 min_confidence=0 表示不按置信度过滤，>0仍筛除未知；这是显示筛选，不改推荐选择/预算、投注、新闻发布、人工审核或财务门禁，不重算历史票单。其他消费者的全链路迁移由 P107 负责。

## 限制与验证

十维完整度算法保留。它表示现有维度覆盖，不是预测准确率、真实全赛事覆盖或来源时效证明。阵容/伤停/战意等既有固定权重、代理和未知状态仍有限制；固定 goal-rate 修正规则保持原样，未当作拟合球员影响或校准概率。

本地测试使用固定样本、模拟游标、内存 SQLite 与合成分类器；可核对 SQL 参数、数据选择、字段/版本、保存调用和概率投影，不替代 PostgreSQL 的真实类型/约束/JSONB/精度/持久化验收。列目录及可空状态对照 P100 已记录本机目录；本批没有连接数据库。容器无网络，源码只读，上传测试目录指向临时内存盘；不调用付费源、生产数据或业务训练任务。

# 比赛中心与首页赛事雷达整合方案与实施记录

日期：2026-10-25（Asia/Shanghai）

状态：本地实施与验证完成，页面整合单独提交至 `main`；尚未推送或部署。本地验证与限制见第 11 节。

## 1. 目标与结论

首页负责快速了解比赛概况，比赛中心负责选赛与分析，比赛详情负责查看单场证据，赛事中心负责浏览联赛赛程与赛果。

推荐把首页“赛事雷达”改为“比赛概览”，把现有数字球场迁为比赛中心内按需打开的可选视图。完整搜索、筛选、选赛、模型概率和官方赔率集中在比赛中心。

本次是前端职责整理。沿用现有主题、组件、接口和数据库，预测算法及数据采集沿原来的模型与数据计划推进。赛事异动告警属于后续独立需求。

## 2. 实施前重叠核对与可复用部分

| 项目 | 首页赛事雷达 | 比赛中心 | 处理方式 |
| --- | --- | --- | --- |
| 官方未结束比赛 | `api.matches.active({ limit: 500 })` | 同一接口与参数 | 统一读取规则；按页面需求呈现 |
| 搜索、选择比赛 | 搜索和滚动列表 | 搜索、联赛/状态筛选、排序和分页 | 完整操作集中在比赛中心 |
| 预测与官方赔率 | `MatchEvidence` | 同一组件 | 首页取消此面板，比赛中心继续复用 |
| 比赛详情链接 | `#/matches/:id` | 相同 | 保留现有链接 |
| 数字球场 | 最多 24 个选赛节点 | 尚无 | 迁为比赛中心可选视图 |
| 定时刷新 | 默认 30 秒 | 同一刷新 Hook | 列表与 3D 共用一个页面数据实例 |

当前底层已经复用 `MatchEvidence`、展示工具、刷新 Hook 和后端接口，重点是减少重复操作入口。客户端已有进行中的 GET 请求去重，尚无跨页面结果缓存；当前单页路由通常只挂载其中一个页面，不能把两处刷新直接算成请求翻倍。

“赛事雷达”现有代码没有独立的赔率异动、阵容变化或异常预警规则。数字球场节点按列表顺序排布，其位置没有球员站位、球队实力或比赛热度含义。

## 3. 页面职责

| 页面 | 用户要解决的问题 | 主要内容 |
| --- | --- | --- |
| 今日驾驶舱 | 现在有什么比赛值得进入查看？系统是否正常？ | 现有经营/运行概览、近期比赛快捷入口、Agent 与管线入口 |
| 比赛中心 | 找到某场未结束比赛并分析 | 搜索、筛选、排序、分页、选中赛事、模型概率、官方赔率、可选 3D |
| 比赛详情 | 核对这场比赛的输入和预测记录 | 现有特征快照、预测记录、阵容与伤停证据及时间说明 |
| 赛事中心 | 按联赛浏览赛程和赛果 | 现有官方赛事目录、联赛分类、比分与状态、详情入口 |

保留 `/`、`/matches`、`/matches/:id`、`/events` 路由。赛事中心首期保留名称与功能，用说明文字明确“联赛赛程与赛果”的用途；以后如需更名，再统一导航、页面标题和语言文案。

现有比赛详情页并非比赛中心分析面板的完整复制，两者目前使用的读取路径和展示范围也不同。本轮保留其证据查询职责，避免在整合中再造详情页。

## 4. 首页：比赛概览

### 展示内容

- 标题“比赛概览”，保留进入比赛中心的明显入口。
- 在已获取的最多 500 场范围内，按有效开球时间展示接下来开球的最多 5 场；显示官方编号、联赛、主客队和开球时间。
- 已开球且等待赛果的记录单独标注为“等待赛果”，不混进“即将开球”；不推断实时比分或正在进行的分钟数。
- 单场“查看分析”跳至 `#/matches?match_id=<ID>`；需要直接查证据时沿用现有详情链接。
- 显示最近获取时间、加载、空结果、失败及失败后保留旧数据状态。获取时间与来源记录时间分开表达。

首页取消完整比赛搜索、500 场滚动选择、数字球场和所选比赛预测/赔率面板。这样首页首次进入不会因为默认选中一场比赛，自动请求该场详情和赔率。

保留 `CommandWorkspace` 对“比赛概览”和“Agent 与管线”的切换能力，后者继续按原方式懒加载。首页比赛区域取消 3D，不影响 Agent 场景的既有开关和行为。

### 数量口径

现有 active 接口的 `total` 等于 LIMIT 后返回数量。首页如显示数量，应写“本次获取 N 场”，并注明上限；不标成数据库全量或“今日全部”。已有首页 KPI 保持各自业务口径，不能拿“体彩在售且已预测”的数量替代“全部未结束比赛”。

如将来需要全量计数，应单独增加数据库聚合能力；这不属于首期实施范围。

## 5. 比赛中心：统一选赛与分析

### 默认列表视图

保留目前的搜索、联赛与状态筛选、时间排序、50 条分页、刷新、预测与官方赔率面板。页面继续说明筛选和分页只作用于本次获取的最多 500 场记录。

增加从首页进入时的选中定位：

1. 校验 URL 中 `match_id` 为正安全整数。
2. 在有效的已获取列表内找到比赛，定位到对应页并选中；若已有筛选隐藏目标，明确提示并允许清除筛选查看。
3. 目标已结束、已移出列表或不在本次获取范围时，说明“当前未结束列表中未找到”，保留该 ID 的详情入口；不把默认首场显示成用户指定的比赛。
4. 搜索、筛选、排序、页码与选中 ID 写入 hash 查询参数；进入详情后返回应恢复原状态。查询参数的变化也需触发同步，不能只在首次挂载读取一次。
5. 非法参数使用安全默认值并提示；未知参数不影响其他页面。

复用现有 hash 路由，无需更换路由框架。返回链接采用固定的站内目标，避免接受任意跳转地址。

### 可选 3D 视图

- 默认显示列表，用户主动选择“打开 3D 选赛”后才加载 `PitchScene` 和创建场景。
- 列表、3D、分析面板共用筛选结果和一个 `selectedId`，3D 不拥有自己的数据查询或轮询。
- 最多 24 个节点，继续显示数量限制和“节点位置只用于导航”的说明；选中范围外的比赛应纳入可见节点，列表始终可操作。
- 关闭或离开视图时卸载场景并释放资源；隐藏页面时沿用暂停逻辑。加载失败或 WebGL 不可用时保持二维操作。
- 赛事 3D 的打开状态独立管理，不通过修改全局 `fqp.scene.enabled` 来连带改变 Agent 场景设置。
- 本轮复用现有导航场景，不增加战术模拟、球员移动、实力柱或未经证据支持的热度效果。

## 6. 代码与数据复用

| 范围 | 计划动作 |
| --- | --- |
| `features/command-center/CommandWorkspace.tsx` | 比赛标签改为概览，保留 Agent 与管线标签及懒加载 |
| 首页比赛概览组件 | 替代原 `CommandCenter` 的完整选赛界面，只展示摘要和链接 |
| `pages/MatchesPage.tsx` 及样式 | 承担统一选赛、URL 状态和可选 3D 容器 |
| active 列表读取与校验 | 抽出一处公共读取函数，统一参数、数量/状态/编号校验；复用 `useReadOnlyResource` |
| `MatchEvidence` 与展示工具 | 复用已有实现，不另写概率或赔率转换逻辑 |
| `PitchScene` / `SceneViewport` | 复用现有渲染与回退能力，由比赛中心决定是否挂载 |
| 原 `CommandCenter`、样式、测试引用 | 完成替换后查引用，删除确定无消费者的部分 |
| 文档和页面测试 | 更新当前职责、入口、选中同步与加载边界 |

共享读取函数代表统一口径；首页和比赛中心仍各自拥有生命周期。暂不增加全局状态库、结果缓存、WebSocket、服务、数据库表或供应商请求。现有 API 客户端继续去重同时进行的相同 GET；不承诺跨页切换完全没有请求。

共享的 CSS、`MatchEvidence`、`SceneViewport` 等仍有其他消费者，清理时按引用判断，不能整目录删除。即使移走首页比赛场景，Three.js 仍被 Agent 及其他场景使用，不因此删除依赖。

## 7. 实施顺序

| 顺序 | 交付内容 | 完成条件 |
| --- | --- | --- |
| 1 | 统一列表读取/校验，接通 URL 选中与返回状态 | 首页指向指定 ID 后能正确选中；异常 ID 有明确说明 |
| 2 | 数字球场迁入比赛中心，默认关闭 | 列表和 3D 共用数据与选择；关闭时不加载比赛场景 |
| 3 | 首页替换为比赛概览，保留 Agent 入口 | 首页不再加载所选比赛分析和赔率，近期比赛可直达分析 |
| 4 | 清理原入口与失效引用，更新文档并回归 | 无重复完整选赛入口，现有详情和赛事目录可正常访问 |

全程在现有 `main` 顺序实施。当前已有模型输入质量的未提交改动应原样保留，避免把界面调整与模型效果改造混成一次验收。

## 8. 验收要求（实施时执行）

- 首页比赛概览挂载后不请求单场详情、单场赔率或比赛 `PitchScene`；如用户打开“Agent 与管线”，其独立请求和场景按原规则工作。
- 比赛中心一次列表读取供列表和比赛 3D 使用；打开/关闭 3D 不新增 active 列表轮询或重复的分析面板。
- 首页快捷入口、分页、筛选、3D、分析与详情始终对应同一比赛 ID；切换选中后旧响应不覆盖新比赛。
- 浏览器返回、前进及直接粘贴链接可恢复选中与筛选；指定目标缺失时不静默替换成另一场。
- 加载失败与空列表分开，失败保留旧数据并标注；缺失概率、赔率和来源时间保持未知，真实零值保留。
- 已停售但未结束比赛继续可查看；已结束记录按既有赛事中心/详情入口查找。
- 手机使用列表可完成全部核心操作；键盘能完成筛选、选择、视图切换及返回，焦点可见。
- 保留 3D 的资源释放、页面隐藏暂停、回退、主题适配与减弱动画行为；不得把历史耐久结论当作此次变更的测试结果。
- 执行相关页面/组件回归、类型检查和构建，再进行必要的浏览器检查；实际结果见第 11 节。

## 9. 后续事项

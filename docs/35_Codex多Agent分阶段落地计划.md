# 35. Codex 多 Agent 分阶段落地计划

## 阶段 A：基础 Agent 框架，1-2 周

### 目标

建立 Agent 注册、权限、任务队列、审计日志。

### 交付物

- `agent_registry.yaml`
- `agent_permissions.yaml`
- `agent_tasks` SQL
- `agent_audit_logs` SQL
- `scripts/agents/orchestrator.py`
- `scripts/agents/agent_registry.py`

### 验收

- 能创建任务。
- 能分配 Agent。
- 能记录状态。
- 能记录文件变更和命令。

## 阶段 B：Codex 开发工作流，1-2 周

### 目标

让 Codex 按标准提示词执行开发任务，并由 QA Agent 验证。

### 交付物

- Codex 提示词模板。
- 开发任务模板。
- QA 测试模板。
- Pull Request 审查模板。

### 验收

- 任意代码任务都能按模板执行。
- 测试失败能生成修复任务。
- 文档能同步更新。

## 阶段 C：数据采集 Agent，2-4 周

### 目标

官方赛程、赔率、赛果、球队/球员/伤停/天气数据采集任务全部任务化。

### 交付物

- 官方赛程采集 Worker。
- 官方赔率快照 Worker。
- 天气采集 Worker。
- 伤停首发采集 Worker。
- 数据质量检查 Worker。

### 验收

- 官方源异常触发熔断。
- 快照不可覆盖。
- 采集失败生成修复任务。

## 阶段 D：AI 计算 Agent，3-6 周

### 目标

由 Model Agent 维护模型计算脚本，由 Scheduler/Worker 执行长期计算任务。

### 交付物

- Poisson 计算任务。
- Dixon-Coles 计算任务。
- 赔率转换任务。
- 多维特征构建任务。
- 模型委员会投票任务。

### 验收

- 每次预测绑定赔率快照和特征快照。
- 模型不能使用赛后数据。
- 输出包含不确定性和置信度。

## 阶段 E：推荐与风控 Agent，2-4 周

### 目标

候选推荐自动生成，正式推荐必须经过 Risk Agent。

### 交付物

- 候选推荐生成器。
- 资金分配器。
- 熔断规则检查器。
- 推荐失效重算器。

### 验收

- 连亏、官方源异常、快照缺失时自动停止推荐。
- 每张票有风险等级和资金来源。
- 正式推荐有审核记录。

## 阶段 F：长期运维 Agent，持续迭代

### 目标

Codex 持续维护系统，自动生成修复任务和优化建议。

### 交付物

- 失败任务自动诊断。
- 数据质量日报。
- 模型漂移监控。
- 备份恢复演练。

### 验收

- 连续运行 30 天关键任务成功率 >= 98%。
- 每日复盘成功率 >= 99%。
- 关键失败能在日志中定位并生成修复任务。

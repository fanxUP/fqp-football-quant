# 43 功能面板扩展验收清单

## 1. 新增面板验收清单

| 检查项 | 标准 | 是否必须 |
|---|---|---|
| 面板注册 | 已写入 panel_registry.yaml | 必须 |
| 权限配置 | 已写入 menu_permissions.yaml | 必须 |
| API 契约 | OpenAPI 有对应接口 | 必须 |
| 数据来源 | 明确来自哪个模块 | 必须 |
| 错误处理 | API 失败有空状态和提示 | 必须 |
| 移动端 | 小屏可读 | 推荐 |
| 图表 | 轴、单位、图例清晰 | 推荐 |
| 性能 | 首屏加载不超过目标阈值 | 推荐 |
| 审计 | 有敏感操作记录 | 必须 |
| 测试 | 有前端/接口测试 | 必须 |

## 2. 面板信息完整性

每个面板 README 至少写明：

```text
面板用途
用户角色
显示字段
调用 API
依赖模块
权限要求
异常状态
验收截图
```

## 3. 示例：新增“模型委员会面板”

必须展示：

```text
比赛基础信息
各模型投票概率
模型一致性评分
不确定性评分
最终建议概率
是否进入推荐池
拒绝推荐原因
```

## 4. 示例：新增“战意赛制博弈面板”

必须展示：

```text
当前排名
晋级概率
赢平负对应排名变化
潜在淘汰赛对手
半区路径难度
避强队风险
轮换风险
数据置信度
```

## 5. 版本升级验收

面板升级时必须确认：

```text
旧路由仍可访问或有重定向
旧权限仍兼容
旧字段没有被直接删除
新增字段有默认值
回滚后菜单恢复正常
```

## 6. 最低交付标准

1. 面板可以被启用/禁用。
2. 无权限用户不可访问。
3. 数据缺失时不崩溃。
4. 面板显示的关键数字能追溯到数据库表。
5. 面板上线后能被 Codex 独立维护。

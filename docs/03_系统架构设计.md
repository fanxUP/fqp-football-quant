# 03_系统架构设计

## 架构分层

```text
前端 Web / H5
        ↓
API Gateway / FastAPI
        ↓
业务服务层
├── 官方数据服务
├── 数据治理服务
├── 模型预测服务
├── 推荐引擎服务
├── 实票服务
├── 复盘报表服务
├── 回测服务
└── 传统足彩组合服务
        ↓
数据层
├── PostgreSQL
├── Redis
├── 对象存储/本地票据图片
└── 日志与备份
        ↓
任务层
├── APScheduler（当前） / Celery（预留，不启用）
├── 官方采集任务
├── 赔率快照任务
├── 赛果结算任务
├── 推荐生成任务
├── 日/周/月报任务
└── 模型训练/回测任务
```

## 推荐技术栈
- 后端：Python 3.11 + FastAPI + SQLAlchemy + Alembic；
- 任务：APScheduler；Docker 发布栈保留 Redis 作为缓存与服务依赖，Celery 不作为当前执行链路；
- 数据库：PostgreSQL 15+；
- 前端：Vue 3 / React + ECharts；
- 模型：numpy、scipy、pandas、scikit-learn、lightgbm；
- 部署：源码在 macOS 宿主机开发；日常热开发使用本机进程，发布运行使用受 GitHub SHA 校验的 Docker Desktop Compose 栈；
- 文档：OpenAPI、Markdown、Excel、DOCX/PDF。

## 服务职责

### 官方数据服务
负责采集、清洗、入库、快照、异常报警。

### 模型服务
负责市场概率、Poisson、Dixon-Coles、Elo、LightGBM、模型委员会、概率校准。

### 推荐服务
负责候选筛选、EV计算、资金分配、票单生成、熔断判断。

### 实票服务
负责票据图片、OCR/手动录入、绑定推荐、结算。

### 复盘服务
负责日报、周报、月报、错因归因、策略建议。

## 数据流
1. 官方数据进入 official_* 表；
2. 第三方特征进入 external_* 表；
3. 模型读取特征与赔率快照，输出 model_predictions；
4. 推荐引擎读取 model_predictions 和 bankroll_rules，生成 simulation_tickets；
5. 用户上传实票，写入 real_tickets；
6. 赛果入库后结算 simulation_tickets 和 real_tickets；
7. 报表服务生成 reviews；
8. 回测服务读取历史快照和历史模型版本。

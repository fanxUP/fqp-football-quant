# 20 赛前多维情报预测系统总方案

## 1. 模块定位

本模块用于把竞彩足球/足彩预测从“赔率 + 历史战绩 + 基础进球模型”升级为“官方赔率基准 + 球队赛季数据库 + 球员阵容数据库 + 伤停首发快照 + 球场地理天气 + 赛程动机 + 晋级赛制博弈”的多维赛前预测系统。

该模块不替代官方数据中台。官方数据中台仍然决定：

- 今日哪些比赛可以分析；
- 哪些竞彩足球玩法开售；
- 官方 SP 赔率是多少；
- 赛果开奖如何结算；
- 推荐票单必须绑定哪个赛前官方快照。

多维情报预测系统负责：

- 解释球队真实战力；
- 量化球员身价、首发、伤病、阵容完整度；
- 判断旅行疲劳、球场环境、天气影响；
- 判断联赛/杯赛/小组赛的战意和赛制激励；
- 生成统一的比赛特征快照；
- 给模型委员会提供可回测、可复现的赛前特征。

## 2. 为什么必须做成数据库，而不是推荐文案

这些信息不能只写在推荐理由里，必须结构化入库。原因如下：

1. **可回测**：赛后要知道某个特征是否真的提升预测，而不是凭感觉判断。
2. **可复现**：任意历史推荐必须能重建当时的赛前信息环境。
3. **可审计**：如果推荐错误，要区分是模型错、数据源错、阵容误判、伤病更新滞后还是用户执行偏差。
4. **可降权**：长期无效的特征要自动降权，有效特征要保留。
5. **防止未来数据污染**：赛后首发和赛后伤停不能反向污染赛前预测。

核心原则：

```text
所有赛前信息必须保存 snapshot_time。
所有预测必须绑定 match_feature_snapshot_id。
所有赛后复盘必须只使用推荐生成时已经存在的特征。
所有预测首发、官方首发、赛后实际首发必须分开保存。
```

## 3. 新增十大预测维度

| 维度 | 目标 | 主要用途 | 数据类型 |
|---|---|---|---|
| 球队整体身价 | 判断纸面实力 | 胜平负、让球 | 赛季级/快照级 |
| 首发阵容身价 | 判断本场真实战力 | 所有玩法 | 赛前快照 |
| 替补席深度 | 判断后手能力 | 后程表现、让球 | 赛前快照 |
| 伤病停赛 | 判断战力折损 | 胜平负、总进球、比分 | 球员可用性快照 |
| 阵型与首发变化 | 判断战术稳定性 | 胜平负、半全场 | 首发快照 |
| 球场地理位置 | 判断主客场环境 | 主客场修正、疲劳 | 球场基础表 |
| 天气环境 | 判断节奏和进球 | 总进球、比分 | 天气快照 |
| 赛程密度 | 判断轮换和体能 | 胜平负、让球、半全场 | 赛程衍生特征 |
| 战意压力 | 判断是否全力争胜 | 胜平负、让球 | 积分榜快照 |
| 赛制博弈 | 判断避强队、保平、轮换 | 小组赛/杯赛/淘汰赛 | 场景模拟快照 |

## 4. 模块边界

本模块负责“提高预测解释力和模型输入质量”，但不负责直接输出投注建议。投注建议仍由推荐引擎决定：

```text
多维特征系统 -> 模型中心 -> 市场博弈层 -> 推荐引擎 -> 风控熔断 -> 模拟票单/实票记录
```

如果多维特征数据不足，系统不应该强行填补，而是提高 uncertainty_score，并可能触发“不推荐”机制。

## 5. 数据源要求

每类数据源必须具备以下字段：

```text
source_name
source_url 或 source_identifier
snapshot_time
source_confidence
raw_json/raw_html
parser_version
```

建议数据源分级：

| 等级 | 示例 | 用途 |
|---|---|---|
| A | 官方赛程、官方赛果、官方首发、官方公告 | 可直接进入正式预测 |
| B | 权威数据商、联赛官网、俱乐部官网 | 需要校验后进入正式预测 |
| C | 媒体预测首发、新闻伤停 | 只作为预测首发/风险提示 |
| D | 社媒、小道消息 | 不进入模型，只提高人工关注 |

## 6. 预测时间线

| 时间点 | 数据动作 | 模型动作 | 推荐动作 |
|---|---|---|---|
| 赛前 72h | 初始化赛程、球队画像、积分榜 | 粗预测 | 不出正式票 |
| 赛前 48h | 预测首发、初始伤停、天气预报 | 初版多维特征 | 候选池 |
| 赛前 24h | 更新媒体首发、赛程动机、赔率变化 | 第二版预测 | 候选排序 |
| 赛前 6h | 更新伤停、天气、旅行、战意 | 风险重估 | 预推荐 |
| 赛前 1h | 官方首发确认 | 最终模型重算 | 最终票单 |
| 停售前 | 锁定官方赔率快照 | EV 重算 | 发布/熔断 |
| 赛后 | 实际首发、赛果、天气、结算 | 复盘归因 | 日报/周报/月报 |

## 7. 模型接入方式

多维特征不能简单相加，建议三层接入。

### 7.1 规则修正层

适合 MVP 阶段，稳定可控。

- 核心前锋缺阵：降低球队预期进球 λ。
- 主力门将缺阵：增加对手预期进球 λ。
- 两名中卫缺阵：提高大球和丢球风险。
- 首发未确认：提高不确定性，不强行改变方向。
- 客队旅行疲劳高：降低客队下半场强度。
- 大雨/大风：降低传控型球队优势，提高总进球不确定性。
- 已提前晋级：提高轮换风险。
- 存在避强队路径：降低强队主动争胜动机，增加平局/保守策略权重。

### 7.2 特征模型层

输入 LightGBM/XGBoost/Logistic Regression/Calibration Model。

主要特征：

```text
market_probability
elo_diff
poisson_lambda_home
poisson_lambda_away
team_market_value_diff
starting_11_value_diff
lineup_strength_diff
absence_impact_diff
rotation_risk_diff
travel_fatigue_diff
weather_impact_score
motivation_diff
tournament_incentive_risk_score
odds_movement_score
uncertainty_score
```

输出：

- 胜平负概率；
- 让球胜平负概率；
- 总进球概率；
- 比分矩阵修正；
- 推荐置信度；
- 不确定性惩罚。

### 7.3 模型委员会层

模型委员会由多个子模型投票：

- 官方市场概率模型；
- Elo 模型；
- Poisson 模型；
- Dixon-Coles 模型；
- 球队身价模型；
- 首发阵容模型；
- 伤停影响模型；
- 天气旅行模型；
- 战意博弈模型；
- 赔率异动模型。

只有多个模型方向一致，并且数据完整度达标，才能进入主策略池。

## 8. 页面展示升级

比赛详情页新增“多维情报评分”。

```text
球队身价优势：主队 +18
首发阵容优势：主队 +9
伤停影响：主队 -14
旅行疲劳：客队 -11
天气影响：中等
战意优势：客队 +6
赛制博弈：主队轮换风险高
数据完整度：86/100
不确定性：31/100
```

推荐解释示例：

```text
主队纸面实力强，但两名主力中卫缺阵，缺阵身价占球队总身价 18%。
客队连续第二个客场，旅行疲劳评分较高。
天气预报显示比赛时段有强风和降雨，总进球模型置信度下调。
主队已提前晋级，小组第一可能进入更强半区，系统提高轮换风险和赛制博弈风险。
结论：主队实力占优，但不适合重仓主胜。
```

## 9. 验收标准

1. 每场比赛可以生成至少 1 个 `match_feature_snapshots`。
2. 特征快照必须包含球队、阵容、伤停、旅行、天气、战意、赛制博弈、数据质量字段。
3. 赛前 48h/24h/6h/1h 不同快照不能覆盖。
4. 预测首发与官方首发必须分开保存。
5. 数据源必须保存 source 和 confidence。
6. 推荐票单必须绑定某个特征快照。
7. 赛后复盘能回溯推荐时的特征值。
8. 特征长期效果必须纳入月报：正贡献、负贡献、无效特征。
9. 数据不完整时必须提高不确定性，不能静默补齐。
10. 赛制博弈结论必须基于积分、排名和潜在对手模拟，不能主观臆测。

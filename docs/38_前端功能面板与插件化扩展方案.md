# 38 前端功能面板与插件化扩展方案

## 1. 建设目标

前端不应该把页面全部写死在主路由和菜单里。FQP 后续会持续新增：

```text
官方赛程面板
赔率快照面板
多维特征面板
球队赛季画像面板
首发伤停面板
天气旅行面板
战意赛制博弈面板
模型委员会面板
推荐票单面板
实票复盘面板
回测中心面板
传统足彩组合面板
Codex Agent 面板
运维监控面板
```

如果每次新增都改核心布局，后期维护会很痛苦。正式项目采用“功能面板注册机制”。

## 3. 面板注册字段

每个面板通过 `panel_registry.yaml` 注册：

```yaml
panel_id: recommendation.daily_recommendation
module: recommendation
name: 今日推荐
route: /recommendation/daily
component: DailyRecommendationPanel
icon: ticket
order: 310
required_permissions:
  - recommendation.view
feature_flags:
  - recommendation_enabled
status: active
```

## 4. 面板类型

| 类型 | 用途 |
|---|---|
| dashboard | 首页卡片、总览 KPI |
| list | 列表查询，如官方赛程 |
| detail | 比赛详情、球队详情 |
| analytics | 图表分析，如赔率曲线 |
| workflow | 操作流程，如实票上传 |
| admin | 后台配置，如模块启停 |
| agent | Codex Agent 任务面板 |

## 5. 面板通信规范

面板之间禁止直接互相引用状态。统一通过：

```text
URL Params
Global Query Cache
Event Bus
Shared API Client
```

示例：

```text
点击“周三001” -> 路由跳转 /matches/{match_id}/features
不要在赔率面板里直接 import 特征面板内部函数
```

## 6. 功能面板扩展示例

新增“天气旅行面板”步骤：

```text
1. 新建 modules/stadium-weather/panels/WeatherTravelPanel.tsx
2. 在 panel_registry.yaml 注册
3. 在 menu_permissions.yaml 配置权限
4. 在 openapi 中补充接口
5. 在 tests 中补充 UI 验收项
6. Codex 生成代码后执行前端构建和测试
```

## 7. 前端验收标准

1. 新增面板无需修改主菜单核心代码。
2. 面板可通过权限隐藏。
3. 面板可通过 feature flag 暂停。
4. 面板路由可自动注册。
5. 面板错误不会导致全站崩溃。
6. 面板数据源在 API 契约中可追踪。
7. 移动端可退化显示核心信息。

# 体彩官方历史比赛回填与审计

## 数据边界

- `official_matches` 只允许写入中国体育彩票 / 中国竞彩网官方曾收录的比赛。
- 用户可见编号必须保存为 `周一001` 这类官方显示编号，不能用 Sporttery 内部数字替代。
- 历史身份优先使用 Sporttery `matchId`；缺少 `matchId` 时，只允许使用 `business_date + official_match_code`。禁止跨日期只按编号匹配。
- 第三方赛程、比分和赔率不得新建 `official_matches`。赛事中心默认只展示 `source=official`。

## 为什么需要本地官方文件

体彩历史赛果接口可能返回 HTTP 403，浏览器访问也可能被 HTTP 567 风控拦截。遇到这种情况，不能用第三方赛程冒充官方历史。可在能够正常打开体彩结果页的浏览器中，保存官方接口响应为 JSON，或在开发者工具 Network 中导出包含响应内容的 HAR。

官方页面：`https://www.sporttery.cn/jc/zqsgkj/`

目标请求：`getMatchResultV1.qry`

## 导入步骤

先做只读校验：

```bash
.venv/bin/python -m scripts.official_history_importer \
  /绝对路径/sporttery-history.har \
  --dry-run
```

只有确认文件是单个官方业务日、且响应行没有 `businessDate` 时，才提供回退日期：

```bash
.venv/bin/python -m scripts.official_history_importer \
  /绝对路径/sporttery-2026-07-10.json \
  --business-date 2026-07-10 \
  --dry-run
```

校验结果中 `rejected` 必须为空。确认后去掉 `--dry-run` 执行写入。导入器会先补建响应中字段完整的官方比赛，再写入赛果，并把文件路径、SHA-256 和官方页面 URL 保存到溯源字段。

## 赛季范围审计

竞彩覆盖多个联赛，各联赛赛季起止不同，因此审计必须显式给出日期范围，不能笼统声称“当前赛季完整”：

```bash
.venv/bin/python -m scripts.audit_official_history \
  --start-date 2026-01-01 \
  --end-date 2026-07-11
```

审计结果：

- `identity_integrity=ok`：本地编号、日期、球队和开赛时间通过一致性检查。
- `source_completeness=unverified_against_official_source`：本地数据尚未与同一日期范围的体彩官方全集逐日核对。
- 只有取得官方逐日响应、完成导入并核对每日场数后，才能在外部报告中标记该日期范围已完整覆盖。

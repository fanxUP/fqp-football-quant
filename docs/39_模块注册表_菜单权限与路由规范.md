# 39. 模块、菜单与路由的事实来源

## 当前入口

| 内容 | 来源 |
| --- | --- |
| 模块身份、依赖与可关闭性 | `configs/final_module_registry.yaml` |
| 菜单名称、路由、排序与可见性 | `configs/final_panel_registry.yaml` |
| 运行时禁用状态 | `data/runtime/module_state.json` |
| UI 接口、分组和禁用检查 | `apps/backend/src/routers/ui.py` |
| 实际前端路由 | `apps/frontend/src/App.tsx`、`core/router.ts` |
| API 认证 | `apps/backend/src/auth.py` |

## 保留规则

1. 新增或修改模块/菜单使用最终注册表中的实际字段。原因：运行时读取 `module_id`、`panel_id`、`route`、`visible` 等字段，旧示例的名称不能替代它们。
2. 修改菜单同时核对静态路由和对应页面。原因：配置中的 route 只提供导航地址，不生成实现。
3. 关闭模块遵守 required、safe_disable 和依赖检查。原因：`ui.py` 会拒绝核心模块、不安全关闭及仍有启用依赖方的操作。
4. 保持后端认证检查，不把菜单隐藏当作访问控制。原因：当前面板接口没有统一执行旧文档中的逐项权限和 feature flag 规则。
5. 兼容已有路由或明确处理跳转。原因：当前应用保留多条旧地址重定向，直接删路由会破坏已有链接。
6. 菜单分组及顺序按实际 UI 接口处理，不另存一套旧分组。原因：分组映射在 `CATEGORY_MENU_GROUP`，顺序来自面板 order。

# 39 模块注册表、菜单权限与路由规范

## 1. 目的

模块、菜单、权限、路由必须配置化，避免后续升级时出现硬编码地狱。

## 2. 模块注册表

模块注册表保存：

```text
模块是否启用
模块依赖哪些模块
模块暴露哪些 API
模块有哪些任务
模块有哪些面板
模块需要哪些权限
模块当前版本
模块负责人和 Codex Agent
```

## 3. 权限命名规范

格式：

```text
module.action.scope
```

示例：

```text
official_data.view.schedule
official_data.manage.source
feature_store.view.snapshot
recommendation.generate.daily
recommendation.approve.publish
ticket_review.upload.ticket
backtest.run.experiment
agent_codex.create.task
ops_admin.manage.module
```

## 6. Feature Flag

每个新模块或新面板必须有 feature flag：

```text
module_enabled
panel_enabled
experimental_enabled
codex_auto_fix_enabled
```

推荐默认：

```text
生产环境默认关闭实验面板
测试环境默认开启实验面板
```

## 7. 菜单加载流程

```text
读取 module_registry.yaml
过滤 disabled 模块
读取 panel_registry.yaml
检查用户权限
检查 feature flag
按 menu_group 和 order 排序
渲染菜单
```

## 8. 验收标准

1. 修改菜单不需要改代码。
2. 新增权限不破坏旧权限。
3. 禁用模块后菜单和路由同步隐藏。
4. 用户无权限时返回 403，不展示敏感数据。
5. Codex 任务不能绕过权限系统。
